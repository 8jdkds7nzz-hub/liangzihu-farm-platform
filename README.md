# 梁子湖智慧农业平台

**把农场的监测、现场作业、空间资料、生产批次和经营证据放进同一个工作空间，让每项处理都能找到对象、依据、负责人和结果。**

本 README 是按当前界面导航整理的功能说明第一版，覆盖 **6 大板块、29 个子模块**。先说明系统服务谁、终端和前后端怎样连接，再逐模块介绍功能、具体操作、技术组成、完成状态与截图。

## 系统定位与使用者

农场的一件事经常跨越多个来源：设备提供测值，工作人员处理异常并拍照，仓管登记收发，技术员审核依据，负责人最后核对这些记录是否属于同一块田、塘口或生产批次。本系统把这些关系连起来，同时保留缺测、未审核、未知反馈和未完成事项。

| 使用者 | 主要工作 |
|---|---|
| 农场负责人、值班人员 | 查看待办和告警，确认任务，跟进处理与交班，审阅简报 |
| 现场人员、仓管人员 | 记录农事、照片、投入品、库存、加工和收发 |
| 技术员、受邀专家 | 核查测值、地形和影像，审核规则、处方、质量与分析依据 |
| 管理员、接入工程师 | 管理对象、设备映射、人员权限、接口契约、后台任务和恢复 |

README展示完整目录；实际页面按角色和对象授权筛选。相同角色也可能只能操作不同对象，管理员身份不自动代替业务授权。

## 整体架构与技术关系

### 终端、前端和后端分别是什么

**终端是设备，前端是界面，后端负责业务处理。** 人员终端和现场设备终端走不同的数据入口。

| 部分 | 本系统中的组成 | 主要职责 |
|---|---|---|
| 人员终端 | 电脑、手机及其浏览器 | 人员查看页面、提交记录、上传照片、审阅事项；手机可保存已准备的现场离线草稿 |
| 现场设备终端 | 传感器、摄像头、无人机、机场、机具终端；执行设备另按协议接入 | 产生测值、状态、影像和作业证据；真实设备与接口仍需逐项核实 |
| 前端界面 | Next.js / React / TypeScript主界面，以及独立现场录入页 | 导航、表单、列表、地图、曲线、三维、上传和状态显示，通过接口读取或提交数据 |
| 后端业务服务 | 同一Next.js工程中的API与业务模块 | 身份与对象授权、输入校验、版本、状态流转、数量关系、审核和查询 |
| 接入与后台任务 | 独立Node.js进程 | 按任务处理只读采集、告警、通知、媒体、知识索引、模型、地形、农情和管理报告 |
| 数据与文件存储 | PostgreSQL、PostGIS、pgvector和私有本地/S3文件存储 | 保存业务记录、空间资料、向量索引、原件、模型、版本及其对应关系 |

### 当前运行方式与共用技术

前端页面与业务API属于**同一个Next.js工程**。接入程序和后台任务分别用独立进程执行，共用数据库和对象授权；前端通过读取或刷新接口查看结果。数据库任务队列负责后台领取、租约、重试和结果状态。

| 技术部分 | 当前使用 | 在业务中的作用 |
|---|---|---|
| 主界面与接口 | Next.js 16.3.8、React 19.2.4、TypeScript | 电脑手机页面、服务端接口、身份和业务处理 |
| 现场离线页 | HTML/JavaScript、IndexedDB、Web Crypto、Service Worker | 本机加密草稿、页面缓存、重连后同步，账号与草稿身份分别核对 |
| 数据与空间 | PostgreSQL 18、PostGIS 3.6、pgvector | 事务和历史记录、对象边界与轨迹、知识向量检索 |
| 地图与三维 | 浏览器SVG、Cesium、3D Tiles | 二维图层、私有模型按需加载、空间与测绘资料核验 |
| 私有文件与影像 | 本地/S3存储、sharp、HLS、GeoTIFF.js | 原件与预览分开、受控视频、实际多光谱格式处理 |
| 本地模型与任务 | Transformers.js、独立Node.js workers | 本地检索与图片候选，以及告警、文件、地形和报告处理 |

接口是前后端交换数据的入口；数据库保存结构化档案和关系，文件存储保存照片、模型等原件。各模块的“技术组成”只补充自己特有的处理，不重复整套通用技术。

## 1. 日常工作

把当天需要处理的事情汇总起来，完成安排、现场记录和异常跟进。

### 1.1 工作台

**页面入口：** `/workbench`

- **实现功能：** 汇总当前账号可见的任务、待核告警和待审简报，提供现场记录与岗位操作入口。
- **具体操作：** 登录后打开工作台 → 查看三类待办 → 点击卡片进入对应事项 → 在具体模块处理 → 返回核对状态。
- **技术组成：** React 工作台通过 `/api/v1/workbench` 读取工作台聚合服务；后端按角色和对象授权查询 PostgreSQL，汇总已有记录，不另造一套任务数据。 [页面源码](<src/app/(platform)/workbench>) · [业务逻辑](<src/modules/workbench>)
- **完成状态：** 软件已实现。待办依赖已登记任务、告警和简报；空列表不代表现场已接管。

### 1.2 告警与核查

**页面入口：** `/alerts`

- **实现功能：** 查看监测异常依据，记录认领、现场核查、复测、处置、恢复、关闭与交班；测量风险和设备问题分别处理。

## 2. 生产业务

### 2.1 库存与批次

**页面入口：** `/inventory`

- **技术组成：** React 库存页面调用 `/api/v1/inventory/[section]`；库存模块采用 PostgreSQL 事务、批次锁、定点数量和不可变分录，防重复并保留转换与交接关系。 [页面源码](<src/app/(platform)/inventory>) · [业务逻辑](<src/modules/inventory>)
- **完成状态：** 通用软件已实现。真实仓位、实物盘点、单位口径及收发凭证仍待 G13 核对。

### 2.2 质量与溯源

**页面入口：** `/traceability`

## 技术与代码定位

```text
src/app/          前端页面与 /api/v1 接口
src/components/   共用表单、列表、导航、地图与三维组件
src/modules/      各业务模块、校验、权限、状态与计算
src/db/           数据库连接及追加迁移
public/field.*    现场离线录入页与浏览器缓存
workers/          独立接入、告警、媒体、模型及报告进程
ops/              环境、健康检查、备份与恢复演练
tools/            初始化、模型准备及工程工具
tests/            单元、隔离数据库、接口与浏览器验收
docs/             设计、计划、执行、验收和岗位操作卡
```

这是独立应用仓库，有自己的锁文件、数据库和私有本机目录。外层“智能体整体方案”是报告与规划工作区，两套应用与数据库分别运行。

## 快速启动

当前提供源码方式的本地启动：Web 与后台进程运行在 Node.js，专属数据库通过 Docker 启动。需要 **Node.js ≥ 22.15.0、pnpm 10.33.0、已启动的 Docker Desktop 和 Git**。首次安装需要下载依赖和数据库镜像。

仓库已公开，新电脑可直接克隆项目；已有工作副本可直接进入项目目录：

```sh
git clone https://github.com/8jdkds7nzz-hub/liangzihu-farm-platform.git
cd liangzihu-farm-platform
pnpm install --frozen-lockfile
pnpm db:setup
pnpm db:migrate
pnpm identity:setup
pnpm registry:setup
pnpm ops:setup
pnpm dev
```

打开 **[本机登录页](http://127.0.0.1:3100/login)**，使用本机 `.local/初始管理员凭据.json` 中的初始账号登录。该文件被 Git 忽略，没有通用公开密码。首次环境默认要求二次验证；已有环境按自身 `IDENTITY_MFA_REQUIRED` 设置执行，详见[登录配置](docs/help/本地开发与运行.md#登录与首次使用)。

初始化只创建农场入口，**不会生成虚构设备、库存或农事记录**。登录后从“配置管理”登记已核实对象及授权；后台计算、告警和媒体处理须另开进程。

<details>
<summary>启动核心后台进程：每条命令单独开一个终端</summary>

```sh
pnpm worker:alarms
pnpm worker:notifications
pnpm worker:media
pnpm worker:knowledge
pnpm worker:intelligence
pnpm worker:image-review
pnpm worker:terrain
pnpm worker:agronomy
pnpm worker:management
```

向量检索与图片模型首次使用前执行 `pnpm models:prepare`；作物候选实验另用 `pnpm models:crop-prepare`。下载权重需要联网，准备后本地推理使用本机文件。作物候选实验默认保持关闭。

</details>

厂家和天气 worker、私有文件存储、登录设置、验证命令及常见问题见[本地开发与运行](docs/help/本地开发与运行.md)。这组启动步骤用于本地开发与核验；生产部署还须完成密钥托管、恢复和现场接入验收。
