# 只读天气接入设计

沿用用户已授权的自主设计开发范围，继续补C01真实HTTP客户端与管理链路。推荐采用和风天气新版`weather/v1/daily`，从现有资料或技术员明确登记的位置读取预报；不从地图邻近猜站点。其他厂家接入仍按实际版本分开验证。

## 本轮范围

1. 实现Ed25519 JWT和新版日预报GET客户端，保存明确单位、UTC区间、源数据标识和归因信息。
2. 新增天气连接配置、审核依据和版本；默认停用。只有当前有配置权限者可以变更，当前有读取和记录权限者才可以提交同步。
3. 采用持久任务执行HTTP读取，HTTP期间不持有数据库事务；执行前后重查当前人员、对象权限及连接版本。网络失败、撤权、配置改变、空数据和成功有不同状态。
4. 同一来源标识/版本防重复；同标识异内容拒绝，不覆盖旧预报。请求次数及未知费用保留，限额不与严重电话预算混用。
5. 原天气表发布时间允许空值。新版公开响应未给发布时间，不用HTTP Date或接收时间填造发布时间。接收时间单独保存，旧记录通过created_at兼容读取。
6. 连接只保存公开设置，私钥、kid/iss/sub在忽略环境文件或密钥服务。整体真实读取开关默认关闭；测试只在agri_test随机schema，使用可控HTTP替身。

## 选择与限制

直接HTTP和Node内置crypto足以实现该接口，无需新增SDK和另一套账号。先做按需同步，后续有真实配额与运行证据后再开启定时调用，避免现在重复请求或假造调度目标。请求host只允许供应商专用HTTPS域名，禁止任意URL和重定向；响应限制大小和时间，错误信息不反射Token或厂家原文。

界面显示连接停用/条件不足、源版本、最后执行结果、预报区间、温度/降水的单位及发布时间未知。预报不显示成现场实况，未给数值不补0。天气归因在界面与简报中保留。
