# 三期3A投入品库存与采收加工详细设计

## 一、目标、人员和主路径

仓管登记批次及仓位→关联采购凭证→实际收货入库→技术员审核质量后领用或加工→现场人员记录施用→采收批次入库→装箱/发货→独立收货确认。每一步保留记录人、发生时间、录入时间、来源和稳定提交标识。

3A实现数量和谱系底座；3B增加检测与放行。初始批次保持待检，入库不自动放行。采购凭证本身不改变库存，发货不自动等于到货。

## 二、页面结构

/inventory分为批次与仓位、采购与施用、库存操作、加工转换、包装与交接。常规操作使用名称选择和单项表单；多行加工/离线资料使用明确定义的JSON文件模板，导入预览逐行展示。列表可搜索并显示当前加载范围。

批次详情显示基本身份、数量口径、当前位置余额、分录、采购/施用、加工输入输出及交接差异。未知毛重、件数或湿度显示未登记。冲销保留原记录入口。

## 三、A31数据契约

| 表 | 核心字段 | 约束 |
|---|---|---|
| stock_locations | object_id、code、name | 对象内code唯一；不预设仓位 |
| stock_lots | object_id、code、product、kind、unit、basis、production_batch_id、identities、state、version | code全局唯一且不可改；kind=input/harvest/processed；unit=kg/L/piece |
| stock_documents | object_id、kind、occurred_at、created_by、evidence、metadata、reverses_id | 操作追加，同一主体同键幂等；冲销唯一 |
| stock_entries | document_id、lot_id、location_id、delta | 数量numeric(20,6)；不可改删 |
| input_purchases | lot_id、supplier、voucher、quantity、occurred_at | 不产生入库分录 |
| input_applications | lot_id、issue_document_id、farm_record_id、quantity、occurred_at、evidence | 必须对应领用；累计施用不得超过该领用量 |
| stock_transformations | object_id、code、kind、source_ref | 长期加工按稳定code追加步骤 |
| stock_lineage | transformation_id、document_id、input_lot_id、output_lot_id | 不允许自环或循环 |
| stock_packages | object_id、code | 物流包装稳定标识 |
| stock_package_events | package_id、lot_id、action、quantity、occurred_at | add/remove累计非负；不自动改变库存 |
| stock_handoffs | lot_id、dispatch_id、direction、party、quantity、occurred_at、document_id | dispatch/receipt独立，累计签收不得超发货 |

identities固定四类：regulatory、inventory、logistics、supplier；每类存明确编号，可空。不得把供应商批号当全局唯一主键。生产批次引用必须属于同一对象；不创建缺失批次占位。

basis=as_is/wet/dry，非kg只能as_is。数量解析为六位定点，范围0至1,000,000,000；业务数量必须大于0，件数整数。API使用十进制字符串返回余额，避免二进制浮点累计。毛重、净重、件数、含水率是独立可空字段；成对已知时毛重不得小于净重。

## 四、A32采购与施用

采购保存供应主体、凭证号/依据、采购量、发生时间。采购量与实收入库量不同也可记录，差异不自动抹平。

领用是库存issue操作，数量离开指定仓位。实际施用另建application，关联领用单、农事记录（若有）、发生时间与依据；原农事记录必须同对象。领出但未施用的量仍可查。重复提交同键返回同一记录；同键改量冲突。将数量全部施用后不得继续分配。

## 五、A33库存事务与更正

| 操作 | 分录 | 额外要求 |
|---|---|---|
| receipt/harvest | 指定仓位加量 | 来源、实际时间；新批次仍待检 |
| issue | 指定仓位减量 | 可用状态、足额余额 |
| transfer | 同批同量从A减、B加 | 两仓位属于本对象且不同 |
| return | 按明确退货方向增/减 | 退货依据；质量状态交3B审核 |
| downgrade | 原批减、新批加 | 同单位同口径、新批明确降级身份，原数量不消失 |
| adjust | 指定盘点差异增/减 | review权限及原因，不能直接写最终余额 |
| reverse | 原分录逐行取反 | review权限；不导致负库存；有下游依赖时拒绝 |

余额由不可变分录求和，客户端不能设置。锁定所涉批次按ID排序取得行锁，查余额和过账在同一事务，避免并发超领及死锁。业务事件与分录同事务提交。输入键锁仅覆盖同一提交，不使用全局业务锁。

未知数量可以留在原资料中等待补充，但不能生成无法计算的库存分录。不同单位、不同基准不允许自动合并。异常以明确400/403/409/422返回，失败事务不留下半笔入库或加工。

## 六、A34采收与加工转换

采收使用harvest类型单据，引用harvest批次、生产批次及依据，入库与可用状态分开。

加工步骤输入/输出各1—20行，引用已存在批次和仓位；不同输入输出不能重复同一批次，输入须可用且库存足额。转换主编号可在多天多步骤复用，每步独立发生时间和单据，不覆盖已记录步骤。

同单位同basis时计算输入合计、输出合计、差额；差额非0必须写明损耗/辅料/计量原因。不同口径只能显示不可直接比较并要求专业审核依据，不自动从湿重算干重。超过输入的产出同样不能默认为正常。输出批次保持待检，原料放行不传递给成品。

谱系输入到输出逐条建立，递归检查防循环。冲销已有下游转换、施用或交接的单据拒绝，先由人员处理依赖，不删除历史图。

## 七、A35包装及交接

包装聚合add/remove独立于加工：装箱不会创造新农产品重量，拆箱不会减少总库存。一个物流包装内可有多个批次，量按批次/单位存；remove不得超过该批累计装入量。

发货记录发货主体、时间、批次、数量、仓位和证据并扣库存。收货在独立时间记录对方确认、实收量，关联dispatch，不自动入另一仓或推定签收。支持分次确认，总和不得超发货；少收量显示待核差异。客户通知不自动发送。

## 八、API和权限

/api/v1/inventory支持分项列表与POST操作：locations、lots、purchases、applications、movements、transformations、packages、handoffs；操作体有requestKey。GET按对象read，record控制登记，review控制盘点/冲销和不等口径加工；所有引用先核read和对应动作。专家仅具体stock_lot授权读取，不能枚举全场库存。

导出使用对象export权限及固定版本phase3-stock-v1，包含批次、分录、数量、谱系及关联依据；原件另按媒体权限下载，不在业务JSON放私有存储路径或凭据。列表最多200条，按对象或已知批次详情收窄。

## 九、事件、恢复与验收

新表追加035_stock.sql；旧000—034保持原字节。所有写动作append领域事件，消费者按既有offset去重，不触发真实告警或控制。

A31验证重复编号、单位/口径、空值和件数；A32验证采购不入库、施用不能超领；A33验证并发领用只一笔成功、跨对象拒绝、冲销幂等；A34验证数量差异、周期拒绝与全事务回滚；A35验证拆包不超量、分次收货差异；A36验证真实浏览器操作、撤权、导出以及所有新表非空恢复。

## 十、完成定义与真实待验

软件完成要求接口和页面可用、上述断言实际通过、类型检查/构建通过、执行记录逐项填写并链接交付。真实仓位盘点、采购单据、实际转换损耗和物流确认仍需现场人员给出。软件不能自动认证库存真实性，也不接入会计核算和四期循环物料全链。
