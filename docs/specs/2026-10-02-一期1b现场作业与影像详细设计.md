## 3. 公共契约

### 3.1 对象、时间与来源

对象ID贯穿边界、农事、附件、任务、摄像头和航次。外部ID只能与已核来源、物理设备或明确通道映射，不能用显示名猜对应关系。

| 字段类别 | 规则 |
|---|---|
| 发生/拍摄时间 | 带时区；未知保持null或阻止依赖真实时间的确认 |
| 接收/保存时间 | 服务器独立记录，不能代替发生时间 |
| 计划时间 | 独立保存，不代实际飞行或现场执行时间 |
| 版本 | 更正追加，保留原值、来源、作者和理由；关联不用名称 |
| 未知数值 | null与0区分，未执行与没有填报区分 |
| 坐标 | 明确原基准和来源；转换后保留来源，不从型号生成位置 |

### 3.2 权限、幂等与事务

业务操作分别要求read、record、configure、review、dispatch、share或export；按钮隐藏不能代替服务器授权。外部专家需对象读取资格加明确事项授权，附件另授权，到期/撤回后再访问失效。

正常提交采用“账号＋稳定请求标识＋规范化内容摘要”，同内容返回原ID，异内容409。事务内行锁和唯一约束处理竞争，不能只靠按钮禁用。文件存储与数据库不是跨系统原子事务：文件写成而数据库回滚时，孤立文件保持私有；重试校验，不能先显示整次成功。

[公共服务](../../src/modules/field/common.ts)提供scope、visible、existingObject、lockKey和sameHash。当前专家事项授权允许record/media/flight等，但没有map类型；地图的专家授权尚未闭环（B-G06）。带时间授权读取还需逐资源核对发生时段，不把对象read当作全部历史资格。

## 4. B01 二维地图

### 4.1 用户流程与状态

管理员录入带来源的对象边界，未确认显示draft；具备review的人员确认后显示verified。没有边界的对象显示缺口，不放置猜测轮廓。用户点击对象进入详情；位置仅用于展示，归属以台账为准。

现有页面是SVG二维边界与设备点位，支持1—3倍缩放和对象点击。图层开关、平移、航次覆盖、成果叠加及历史影像比较尚未实现，不能由“地图页面可打开”判定这些功能通过。

### 4.2 数据与接口

| 实体/入口 | 已有契约 |
|---|---|
| objects | 当前boundary、boundary_status和对象version |
| boundary_versions | 对象ID、对象版本、MultiPolygon/4326、source_crs、来源、draft/verified、确认人及时间；不可覆盖 |
| device_positions | 设备ID、对象ID、Point/4326、位置版本、来源、verified、录入人及时间 |
| GET `/api/v1/map` | 可选bbox=`xmin,ymin,xmax,ymax`；权限内最多500对象、1000设备 |
| POST `/api/v1/map` | 默认saveBoundary；`operation=position`调用savePosition |

saveBoundary接受EPSG:4326、4490、3857，服务器转换到4326；验证有效、非空MultiPolygon及经纬范围。请求带对象当前版本，冲突409；写入新边界版本并递增对象版本。GeoJSON文本上限500000字符，路由正文上限512000字节，两项限制分别生效。

savePosition仅接受明确的WGS84经纬度，有限数值且经度±180、纬度±90；追加位置版本。已有位置API，现有地图表单没有完整的点位录入入口。

### 4.3 补齐设计与验收

B-G01：在现有map模块补图层开关、平移、已确认航次覆盖及同对象成果选择。覆盖需新的不可变版本/来源关联，不修改已应用迁移；未有覆盖不生成占位图形。栅格先按已核坐标生成受控二维预览，禁止直接公开私有文件URL。比较界面并列时期、来源和采集条件，不自动推出产量或病害变化。

B-G06：若专家确需地图上下文，只允许明确分享的对象/航次范围，不开放全场地图；已补固定版本授权、归属校验和接口测试。

验收：边界版本不改变对象身份；错坐标系/无效几何拒绝；bbox无权结果不泄露；关闭某图层只隐藏对应层；同对象两个航次可分别选择并显示条件；没有空间覆盖明确未完成。现有测试只覆盖边界、版本和空间权限，新增项已按本轮代码、空间回归与成果浏览器验证完成。

## 5. B02 农事记录、附件与表格补录

### 5.1 正式提交

流程：选择对象与可用批次→填写发生时间和农事类型→准备原件/预览→逐文件上传校验→提交整次记录→服务器确认全部附件→显示已同步。技术员review追加意见；更正追加新记录，不能编辑历史原件。

| 输入 | 服务端规则 |
|---|---|
| kind | inspection、feeding、fertilization、irrigation、harvest、other |
| observation | 必填，最多4000字符；judgment/action可空，各最多2000字符 |
| material | 投喂、施肥、采收必填；未知用量可留空 |
| amount/unit | amount非负有限数，空值为null；已知用量必须带单位，0保留 |
| objectVersion | 正整数；新提交匹配当前对象版本 |
| batchId | 同对象、已核实、发生时段有效且未被更正替代 |
| attachmentIds | 最多20个、不重复；全部complete、同对象、同创建人和submissionId |
| position | 可选；本人consent=true，经纬合法，accuracy非负，acquiredAt带时区 |

已确认记录的重试先返回原ID，但仍检查当前授权，避免对象之后改版导致响应丢失的老提交重复新增。预期账号不匹配返回ACCOUNT_CHANGED；内容改变必须新建更正，不能换原请求内容重试。

更正要求supersedesId、原expectedVersion和理由；原记录不可覆盖，已有更正子记录时拒绝再次覆盖同一节点。review保存审核人、时间和意见，不等于现场事实由平台保证真实。

### 5.2 媒体存储

| 字段/状态 | 规则 |
|---|---|
| assetId/storageKey | 服务端校验UUID；键由ID与SHA构成，不使用用户路径 |
| checksum | SHA-256，64位十六进制；上传后复读一致才完成 |
| byteLength | 1—20971520字节，即20MiB；当前整体缓冲读取 |
| mime | JPEG、PNG、WebP、PDF、纯文本、CSV、TIFF、MP4；进行文件头核验，未宣称全部格式完整解码 |
| previewOf | 同对象另一媒体；原件与压缩预览分别存，不覆盖原片 |
| capturedAt | 可空；不从接收时间或名称推定 |
| ingestState | pending/complete/failed |
| backupState | pending/verified/failed，复制后复读才verified |

prepareMedia登记元数据；PUT上传检查字节数、SHA与文件头；readMedia重新授权、完整读取并核验字节；媒体响应私有、no-store、nosniff和sandbox。不会向浏览器公开S3凭据或长期公共URL。

本机主目录和副本目录使用0700/0600，拒绝非预期键和符号链接。S3兼容接口已存在；当前第二本地目录只证明复制，不满足独立灾备。备份I/O仍占数据库事务，生产容量下要验证超时和连接占用。

B-G03：当前没有分块上传、视频Range、超20MiB原件的流式校验/续传。航次视频和大型TIFF不能靠调整一个上限交付；必须增加持久上传状态、磁盘/对象存储流式SHA、完整清单确认和中断恢复。源端文件未校验入库及备份前不自动删除。

### 5.3 表格补录与入口

GET/POST/PATCH `/api/v1/records`分别列表、提交（更正也用POST并带supersedesId）、审阅；POST `/api/v1/records/import`逐行导入，最多200行。稳定importId＋原行号生成行标识，SAVEPOINT隔离可预期行错误；重试不复制成功行，返回原行号和具体失败原因。非预期系统错误回滚整批。

POST `/api/v1/media`准备；PUT/GET `/api/v1/media/{id}`上传/受控读取。现有`/records`支持表单与CSV入口，测试覆盖幂等、附件中断、更正、备份及逐行结果，不代表所有真实手机和文件格式通过。

## 6. B03 手机离线

### 6.1 本机存储与用户提示

静态入口`/field.html`、`field.js`、`field.css`由Service Worker缓存；业务API不缓存。首次准备必须联网识别账号，只保存该账号可record的对象及批次。

IndexedDB `agri-field-v1/vaults`按账号保存加密封包。PIN至少6位；PBKDF2-SHA256/210000次、随机16字节salt，AES-GCM/256位、随机12字节IV，账号作AAD。PIN与明文密钥不持久保存。加密不表示已实现遗失设备远程擦除或PIN恢复。

| 草稿状态 | 用户意义 | 允许动作 |
|---|---|---|
| local | 表单/照片已经本机加密写入，服务器未确认 | 编辑、手动同步 |
| pending | 已开始同步；网络、权限、附件或确认仍有问题 | 保留稳定内容重试，显示错误 |
| synced | 服务器确认记录与全部附件 | 查看服务器ID；正式更正走新版本 |

当前现场表单最多5张，每张原片≤10MiB，JPEG/PNG/WebP；原片保留，另生成最长边1280像素、质量0.8的JPEG预览。该限制小于通用媒体20MiB，二者不混写。

### 6.2 同步与异常

同步前请求`/api/v1/me`；账号ID不匹配保留草稿并拒绝上传。先用稳定提交ID询问整次记录，附件缺失才补上传，再确认记录；防止确认响应丢失后重新生成ID。服务端重新检查当前对象、批次、权限和附件。

关闭页面后PIN解锁；旧账号被删除重建时，不自动迁移草稿。撤权、对象冲突、磁盘不足、坏PIN、网络不可达必须保留失败状态，不显示成功。只有local草稿直接可编辑；pending异内容修订需要明确生成新提交/更正，不偷偷改变稳定请求。

目前重新开页和恢复网络后会重试pending草稿；没有后台关闭应用仍保证上传的承诺。已解锁页面在锁定前存在明文内存，部署需HTTPS和终端告知。企业微信自动登录能力与真机兼容仍按账号/终端联调验收。

验收用本机390×844浏览器已覆盖断网保存、关页重开、原片/预览、部分上传失败、响应丢失、账号隔离及撤权保留。它不是iOS、Android或企业微信真实终端验收。

## 7. B04 摄像头事件、原件与能力

### 7.1 事件主链

接收核实设备/来源→按sourceId＋externalEventId防重→同事务创建camera_events、camera类型告警、alert.opened及notification.plan→独立获取图片→原件校验并关联→独立图片复核。图片失败不另建告警、不重置认领或阻断首次通知。

camera_events保存设备、来源、契约版本、发生/接收时间、原payload摘要、alertId及assetId。原始事件不可覆盖；重复ID异内容409，图片只允许关联同对象完整image原件，不替换已经关联的原件。

GET/POST/PATCH `/api/v1/cameras`分别列表、通用事件接收、关联图片。当前图片后补不会自动排`image.review`；1c仍要手工提交复核（C-G09）。

### 7.2 萤石签名入口与远程文件

POST `/api/v1/ingress/ezviz/{id}`采用已核新版消息契约：原始UTF-8正文＋时间头签名、5分钟时间窗、256KiB正文上限。连接默认停用，Secret只在私有环境配置；可靠事务提交消息和处理任务后才确认。

签名消息ID与业务告警ID分别防重。ys.alarm按已核字段映射；SN、通道和来源矛盾保留待核。ys.open.isapi当前不猜字段，状态awaiting_contract。账户授权及开通后原APP提醒变化按[萤石专项设计](2026-10-02-萤石签名消息接入设计.md)办理，当前未开通真实服务。

图片准备任务持久化；无图片、加密图片、下载关闭、失败分别显示。已解密且获许可链接进入media.import，URL加密保存，不回显令牌。HTTPS、精确允许域名、公网DNS/固定解析IP、证书、最多3次重定向、总20秒/20MiB限制；不发送Cookie、凭据或Referer。镜头提供的图片无厂家SHA时只证明下载字节完整，不能宣称厂家原件签名认证。

### 7.3 播放、抓拍与预置位

camera_capabilities保存契约、机型、固件、证据及verified能力。getCameraCapability已检查read与能力，但即使verified也返回adapter_not_connected，现有路由没有完成真正取流、回放、抓拍或预置位调用。

B-G05：真实播放/抓拍接入还需厂商能力适配、当前权限、临时令牌与费用边界；预置位属于设备动作，保持关闭，不能因“能力表有字段”自动启用。未核机型不展示可成功按钮。

## 8. B05 航次和影像成果

### 8.1 通用航次契约

| 实体 | 核心信息 |
|---|---|
| flights | 对象/来源/稳定外部航次ID，真实起止时间，机型/机场/平台版本，sourceRef、CRS、采集条件、载荷和manifestHash |
| flight_files | 外部文件ID、类型/版本、SHA、父文件ID、加工来源、波段、校正及私有assetId |
| flight_annotations | 航次ID、note；表有assetId/location，现有annotateFlight只写文字 |

importFlight清单1—500文件；SHA必填、稳定文件ID唯一、父成果同清单且不能循环；同来源航次ID异清单冲突。文件关联要求同对象、complete、SHA与清单一致；complete与backupComplete分别推导。

API：GET/POST/PATCH `/api/v1/flights`列表/导入/文件关联；POST `/api/v1/flights/annotations`追加注记。当前疑点注记没有落图、没有写文件或几何位置（B-G02）。已有footprint列没有导入/展示链路（B-G01）。

### 8.2 司空只读适配

在[司空专项设计](2026-10-02-司空公有云只读任务与原件接入设计.md)限定的公有云V2契约内，读取指定taskUUID的详情与媒体清单；只GET，连接、读取和文件下载均默认关闭，不发起飞行、同步删除或控制。

dji_connections/versions保存核实配置；dji_runs记录sync/file尝试和授权版本；dji_snapshots保存加密原响应、配置版本、计划时间和清单；dji_resources保存文件元数据、URL密文、下载和备份状态。真实秘密不进入公开接口。

人工确认航次必须分别确认：实际航次ID、实际起止时间、机场与飞机及序列号、坐标/垂直基准、全部清单属于该次实际飞行。计划begin/end不代实际时间；机场SN不代飞机SN；媒体创建时间不代拍摄时间。

司空结果最多10000资源时提示完整性边界；当前列表最多显示1000，确认实际航次仍最多500，超限不能静默截断后标完整。文件当前仅已识别图像及MP4、已知正长度且≤20MiB。PPK、模型包及大型栅格未实现。签名URL变化不冒充文件内容变化。

读取前后核当前授权、来源契约、配置版本及租约；未知中断不自动重复查询。每个HTTP阶段记录尝试与配额，跨月重新检查。完整快照＋原件恢复已有隔离库证据，真实账户、机型和大规模容量待G08。

### 8.3 比较与疑点补齐

B-G02：疑点应关联具体文件、明确坐标/像素位置及标注版本；不能只留一段无法定位的note。几何须同对象/同航次及坐标基准校验。图像像素位置与地理位置区分，没有定位条件只支持图像内标注。

跨期比较按同对象、可比采集条件和覆盖呈现；原片与加工成果分别选择，保留加工父链。不做一键农业诊断、三维或多光谱分析。

## 9. B06 日历、任务、巡查和人工灌排

### 9.1 审核日历

calendar_versions已有species、nullable variety、stage、sourceRef、items和effectiveFrom，不能再把“没有品种字段”列作缺口。每版1—100事项，startDay 0—1000、endDay≥startDay，标题≤200、指引≤3000；正文不可覆盖。

saveCalendar创建版本，reviewCalendar批准/撤回；撤回后须新版本。calendarWindows只匹配同物种、同品种（null精确匹配）、同阶段的已核实有效批次和已审核未撤回日历。

当前按批次开始后每24小时floor计算日龄，含首尾日。生产采用播种/移栽/放养等哪一个起点，以及自然日还是24小时日龄，需专业签认；不能让模型改定义或生成剂量。

GET/POST/PATCH `/api/v1/calendars`分别列表、新版本、审核/撤回。时间窗仅用于建议草稿，不等于正式派单。

### 9.2 任务状态与权限

| 操作 | 状态变化 | 必须条件 |
|---|---|---|
| createTask | 新建draft | record、同对象来源引用、稳定请求ID |
| dispatch | draft→dispatched | dispatch＋confirm=true；接收者可用且有该对象record |
| claim | dispatched→claimed | 指定接收人，行锁、版本匹配 |
| report | claimed→reported | 当前领取人；观测/判断/实际动作分别填，发生时间独立 |
| review | reported→reviewed | review；留意见与事件版本 |
| handover | claimed→dispatched | 当前领取人；解除claimed_by、留痕 |
| amend/cancel | 改未完成指引/结束为cancelled | 当前动作权限、版本冲突校验、记录理由 |

field_tasks和field_task_events保留状态、版本、指令及请求摘要，inspection_reports独立保存观察、判断和动作。GET/POST/PATCH `/api/v1/tasks`为列表、创建和状态操作。

B-G04：现有handover没有改变assignee_id，同一个人释放后才能再领；还不能完成从甲到乙的正式跨人交班。补齐明确重新指派动作，接收人当前权限校验，旧领取人失去后续report资格，完整保留原任务与交班原因。只改按钮文案不能关闭缺口。

### 9.3 人工灌排

irrigation_entries按application→confirmation→execution→result追加；不能执行则not_executed与execution互斥。confirmation要求dispatch，执行需当前领取人及正确任务状态；每步骤发生时间、details、操作者不可覆盖，重复同内容幂等。

POST `/api/v1/irrigation`只写台账。执行记录不证明已给闸门发命令，不依据地图邻近推断供排水路线。实际闸门状态/反馈接入属于另行验收。
