技术员看到可复算的指标、资料引用、异常及缺口，再逐项采纳、修改或驳回。老板收到管理摘要，工人收到已确认的工作内容，专家只接收明确分享的事项。大模型解释不授予权限，不直接派单、分享或控制。

| 层次 | 当前状态 |

## 2. 架构、职责与数据方向

复用一套业务库与权限，程序先计算事实，检索只取审核资料，模型追加解释，技术员确认之后才可转任务草稿。实时采集、告警和电话不依赖文字或图片模型就绪。

| 职责 | 现有文件 | 输入→输出 |
|---|---|---|
| 指标 | analysis/service.ts、calculate.ts | 审核定义＋有效测值→不可变结果版本 |
| 天气 | weather/service.ts、connections/weather.ts | 分类来源/日预报→天气记录与同步证据 |
| 知识 | knowledge/service.ts、chunks.ts | 已识别文本→审核文档/分块/向量/引用 |
| 问答 | assistant/service.ts、provider.ts、validate.ts | 权限内事实/资料→程序结果或经校验的模型解释 |
| 简报 | briefings/service.ts、schedule.ts | 指标、告警、天气、日历、任务→待审事项与发布快照 |
| 图片 | image-review/service.ts、workers/image-review.ts | 原事件完整图片→检测结果追加与现场样本 |
| 评测 | tools/evaluate.ts、tests/evaluations/ | 冻结合成问题集→逐轮检索报告 |

表中模块文件均位于`src/modules/`。模型由受限环境独立CPU进程运行，向量与图片各有固定模型版本，子进程不继承数据库和外部API密钥。

后台使用现有jobs持久队列。天气、萤石、司空和原件导入已有租约结果检查；助手与图片处理函数尚未接收JobLease，知识索引仍在长事务内推理。这是代码缺口，不能写成“所有后台都已满足可靠性”。

## 3. C01 指标定义与计算

### 3.1 定义、审核和输入

metric_definitions保存objectId、pointId、name、version、specification、sourceRef、批准人与时间、retiredAt。正文不可覆盖，修订新版本；未审核或已撤回不能新算。专业审核人对公式及参数负责，模型不能替其生成生产参数。

| specification | 当前规则 |
|---|---|
| formula | mean、min、max、coverage、duration、gdd |
| inputUnit/unit | 输入输出明确；均值极值同单位，duration为分钟，coverage为比例，gdd为温度积量 |
| intervalMs | 1000—86400000毫秒 |
| maxGapMs | 不小于intervalMs，最多31天 |
| minimumCoverage | 0—1，由专业依据审核，不沿用合成测试值 |
| duration | threshold及lt/gt比较方向 |
| gdd | 基温/上限、时区、起点、物种/品种/阶段和专业来源 |

定义必须与同对象的已核测点归属及单位相符，不做隐式单位转换。计算from/to带时区、正窗口≤366天；未来开始拒绝，未结束窗口明确只算已发生部分。最多100000条样本，超出当前规模应分窗，不能静默丢样本。

### 3.2 已实现的算法含义

| 算法 | 当前计算口径 | 不允许的推断 |
|---|---|---|
| 均值/极值 | 采样时间归窗，canonical有效且单位一致；保留全部有效样本 | 不用接收时间移动窗口，不把同槽多条有效值全部压成一条丢极值 |
| 完整率 | 唯一有效采样槽数/ceil窗口槽数，最大1 | 完整率不等于设备通信在线率 |
| 超标时长 | 相邻有效观测、间隔≤maxGap、满足阈值；坏样本打断 | 不向最后一条之后外推，不跨长缺口累计“连续超标” |
| 积温 | 审核时区的完整自然日；日均温按基温/上限计算，每日检查覆盖 | 缺一天不补0，未满足起点和批次条件不推提前天数 |

metric_results保留definitionVersion、窗口、calculatedAt、value、observedValue、unit、status、coverage、limitations、evidenceIds、inputHash和version。usable/insufficient/incomparable分别返回；不足时value为null，observedValue可保存已观测统计，不作为可用结论。

同定义/窗口/输入摘要重复返回原结果；补传改变输入后追加重算版本，旧值不覆盖。计算后发现晚到样本会标历史重算限制；它不自动触发实时电话、关闭告警或冒充最新值。

API：GET/POST/PATCH `/api/v1/analysis`列表/定义/审核；POST `/api/v1/analysis/calculate`按审核定义计算。现有主要是手工计算及清晨简报时计算，尚无总体设计要求的每小时调度或完整补传重算任务链（C-G06）。

### 3.3 往年可比和物候

现有comparisonAllowed只检查比较条件，尚未形成“今年比往年提前/推后多少天”的可复算产品链（C-G11）。缺口包含软件与G09历史专业数据，不能只列为待提供数据。

补齐必须明确同物种、品种、阶段、站点/对象、时段、积温起点、公式版本和输入质量；先产生可比/不可比及原因，再计算有定义的阶段日期差。不可比不产生天数，完整证据可回到原站点、数据和定义。农事/人工干预并列复盘，不自动归因。

## 4. 天气只读接入与分类

weather_records区分actual、forecast、warning、baseline，保留来源/版本、站点、publishedAt、validFrom/To、content、comparisonBasis与received/created时间。021迁移允许publishedAt为null，未知发布日期不填接收时间。

GET/POST `/api/v1/weather`为列表和受控人工导入；天气连接与sync接口提供和风日预报只读链。配置、配额、来源核实、JWT、固定请求路径、加密原响应、授权/配置/租约前后检查见[天气专项设计](2026-10-02-只读天气接入设计.md)。

实际HTTP客户端当前只接日预报1—10天；实况、灾害预警和往年基线可人工登记，未有相应真实来源适配。数值0保留，tag用于来源防重；预报不能代农场传感器实测。

真实账号、网格/站点代表性、服务权益、费用和自动拉取频次须核实。日预报接通不代表天气所有类别完成，也不能据此判农业风险阈值。

## 5. C02 审核知识、检索和引用

### 5.1 资料生命周期

createDocument只接受已识别和校核的text/markdown，正文≤200000字符、标题≤200、版本≤100、对象1—20个、sourceRef≤2000，证据性质必填。当前不解析PDF、DOCX或OCR；原件应先受控识别并核对，再录入，不把文本接口当作多格式导入完成。

knowledge_documents保存正文、sourceRef/URL、版本、对象范围、evidenceNature、sourceChecksum、状态和审核/撤回。sourceChecksum当前是`payloadHash(body)`的规范化JSON字符串摘要，不能冒称原始文件SHA。

状态draft→approved或withdrawn；撤回版本不能复活，修订另建。同来源版本异正文/标题/范围/URL冲突。来源URL不含临时查询参数、片段、凭据。多个已审核版本可以共存，现有程序不会自动指定“最新版即权威”；专业来源替代要明确撤回和审核。

### 5.2 分块、索引与权限

Markdown按标题、段落和表格切分，最大400字符；长段重叠100字符，保留标题路径和表头。中文关键词为双字词＋农业词条，最多1000词，GIN辅助匹配。

BGE使用本地中文small-zh-v1.5 ONNX/q8，512维、CLS归一化，修订`75c43b069aac4d136ba6bc1122f995fedcfd2781`。维度/有限数和模型版本校验；不使用假向量代就绪。

approve后排knowledge.index。当前indexDocument持有文档FOR SHARE并在数据库事务内等待分批CPU推理，撤回要等索引结束（C-G03）。本轮以受控阻塞函数复现撤回100ms锁超时，不代表实际平均撤回一定100ms失败。

补齐设计：短事务读取已审核文档版本/摘要→事务外推理→短事务重核状态、版本、内容、任务租约→写向量；撤回不等待整段推理，旧向量结果不得进入新检索。任务中断允许安全重算，但禁止过期执行者写回。

### 5.3 查询与引用

| 方式 | 当前口径 |
|---|---|
| keyword | 授权且approved文档内按词交集排名，取20候选 |
| vector | 同一EmbeddingVersion精确余弦查询，取20后过滤similarity≥0.45 |
| hybrid | 两路RRF，k=60；默认前5，最多10 |
| vector不可用 | 退关键词并附限制，不编造语义结果 |

查询在距离计算前限制可访问资料。一个文档涉及多个对象时，当前要求用户拥有全部对象读取资格，是保守的整文档范围。外部专家还要明确knowledge事项授权。

Evidence含documentId/version/chunkId/title/heading/text/scopeObjectIds/sourceRef/URL及citationUrl。GET `/api/v1/knowledge/chunks/{id}`每次重新授权；未审核或撤回仅返回source_inactive，不返回原文。

API：GET/POST/PATCH `/api/v1/knowledge`；GET `/api/v1/knowledge/search?q=...&mode=...`；受控引用GET。0.45相似度与400字符是当前工程选择，尚未由真实专业集证明最优；是否重排由同集质量与延迟比较决定。

## 6. C03 事实问答、主备模型与预算

### 6.1 创建、准备和可见性

requestAssistant接收对象1—20个、question≤2000和requestKey≤120；当前read及专家knowledge/metric事项资格核实后创建run＋assistant.generate。账号、authVersion、对象范围、输入摘要、prompt/retrieval版本保留；同标识异问题冲突。

runAssistant生成本地查询向量，检索审核知识，选当前审核未撤回定义的指标；别名O1等代真实对象名，去除姓名、电话、邮箱、精确定位和URL。文字模型不接收人员图片或全场资料。

事实包含ID、status、value/unit、限制和证据；模型上下文只带当前允许内容。无资料且无事实为no_evidence，有依据而真实外发关闭为program_only。readTool只允许metrics/knowledge及对象/起止时间白名单，不接任意SQL或工具名。

现有listAssistant会重新核知识来源和对象资格；对旧回答中的指标事实，未完整重核定义是否已retired（C-G05）。历史回答不能因为“当时可用”继续作为现在有效建议。

### 6.2 外发条件和主备切换

Kimi主、DeepSeek备；具体型号由私有配置固定。真实HTTP客户端要求全局MODEL_EXTERNAL_ENABLED=1、对象externalEnabled、明确approvedScope、限额和许可；默认关闭。当前HTTP请求20秒、非流式、4096输出token、JSON输出约束。

主模型MODEL_TIMEOUT被视为结果未知，不盲目备发；其他错误在全部对象allowBackup时可以备发。现有备发使用先前读取的policy，未在第二次网络请求前重新核全部授权/外发/备用许可（C-G04）。必须每次外部调用前后重新验证，撤回后不再发送。

C-G13：响应目前response.text()后才检查100000字符，缺真正流式读取上限；响应头之后的读取超时也未统一转换为未知结果。补齐字节/时限限制和错误归类，不能把可能已产生费用的读取异常误当可安全重试。

### 6.3 预算与账本

model_policies按对象保存启用/备用许可、月tokens/调用上限、输入/输出单价、价格依据和批准范围。模型额度与严重告警电话预算分开。

当前按`(上下文JSON字符数×4＋4096)×2`保守预留token，预留2次主备调用；按对象/月加锁防并发超额。金额上限已配置但单价未知时阻止真实外发，程序结果保留；未提供单价时费用显示未知，不编造0元。

model_reservations保存reserved/settled/unknown/cancelled及实际用量；usage_events分类别统计、80%提醒与上限。现有最终结算读取当前policy价格，未固定本次调用价目快照（C-G04）；改价不能改变过去这次调用成本依据。

请求跨月、真实失败是否收费、provider实际usage与主备差异须实账对账。未知结果不立即释放预留，不无限保留而没有人工核对入口。

### 6.4 结果校验与状态

validateAnswer要求1—10条claims、每条解释≤2000、有选中evidenceIds/metricIds、同授权范围、数字可对照来源和必要限制；focusItems必须全部覆盖。错误引用、遗漏限制或非法工具不能写成正常解释。

这些检查不能证明农业语义正确、因果正确或剂量可执行；专业人员仍逐项判断。

| 状态 | 页面含义 |
|---|---|
| queued/running | 待执行/正在执行 |
| program_only | 程序事实与审核资料可用，未形成模型解释 |
| no_evidence | 授权范围内没有足够依据 |
| answered | 结构/引用检查通过，仍需人审 |
| validation_failed | 模型输出未通过程序检查，保留程序结果 |
| budget_limited | 预算或价格条件不满足 |
| access_revoked/source_inactive | 当前资格或来源已失效 |
| service_unavailable | 外部模型未完成，继续程序结果 |

C-G01：当前workers/intelligence.ts只传runId；运行超过默认60秒租约或旧任务恢复后，处理函数仍可写业务结果。进程中断可能留下running与保留额度；页面120秒后显示result_unknown只是显示计算，不是持久恢复状态。

补齐：传JobLease，每次推理/外发前与写回时检查token/到期；区分尚未外发的可安全重算与已外发结果未知；持久记录attemptId、未知状态与预算待核，不自动再发、不把旧结果接到新租约。

GET/POST `/api/v1/assistant`；POST policies、tools为受控政策/只读工具接口。以上补齐不能借机增加自动工具执行或代理自治派单。

## 7. C04 程序简报、审阅与发布

### 7.1 程序事实组成

createBriefing要求record，对象1—20、daily/weekly/monthly、from/to正窗口≤31天、稳定requestKey。保存briefings、reviewDueAt（创建后4小时）和不可覆盖的originalText/limitations；模型解释另关联assistant run，不替换程序事项。

| 现有来源 | 当前行为 | 仍有缺口 |
|---|---|---|
| 指标 | 取windowStart在报告期内的最新重算版 | 未约束windowEnd、未联查定义撤回；可能把跨期/已撤回指标写入新报告（C-G05） |
| 告警 | 列当前未关闭，非仅本期新警 | 要明确“当前未结事项”，不假称本期发生 |
| 天气 | 重叠时期的forecast/warning，保留过期/预报限制 | 当前只有日预报真实软件适配 |
| 日历 | 报告截止点的已审核匹配窗口 | 不给剂量，不等于整个周期日历汇总 |
| 任务 | 当前未reviewed/cancelled的待办 | 应与周期内完成记录分开 |
| 农事/维护/人工干预 | 当前未生成相应简报事项 | 尚未完成总体设计要求的并列复盘（C-G08） |

无指标、天气或日历分别生成data_gap/weather_gap/calendar_gap，不把缺口改写为正常。

### 7.2 周期、调度与故障

手工创建支持日/周/月；现有briefing_schedules只有每天上海时间hour/minute，lastDay防重复，自动重算前一日指标或从startDate累计积温后生成日报。周/月自动调度尚无，小时指标也尚无（C-G06）。

generateDue当前把全部到期对象和计算放在一个事务，一条坏定义可回滚整轮并使进程退出。补齐每对象/定义独立任务与失败记录，程序简报仍生成数据缺口；不能因一塘定义失败阻止其他对象或实时链路。

### 7.3 审阅、任务和角色版本

reviewItem要求review及版本匹配，adopted/modified/rejected均存理由、人工文本和review事件；原稿保留。已转任务事项不能原地改审批，需修订。

toTaskDraft仅对采纳/修改项建立draft，必须人工dispatch才能正式派发；不会由模型直接执行。当前重复转任务返回字面state=draft，即使真实任务后来变化；简报state也没有随最后一项审阅更新，页面可能仍报overdue（C-G07）。

老板/技术员/工人版是原定范围；外部专家使用明确分享版。现有publishBriefing只是roleVersion标签不同，同事项snapshot内容相同，未分别生成管理摘要、专业依据和现场指引（C-G07）。

补齐按程序模板生成：老板版保留风险/缺口/待决事项；技术员版保留定义、证据及审核细节；工人版只显示已确认的任务内容、对象、时间和反馈要求；专家只含明确授权事项。各版保留限制，不能把未审建议包装成作业命令。模板分版不要求额外外部模型调用。

### 7.4 发布、撤回和提醒

publishBriefing要求share＋read、confirm=true、指定接收人和itemIds，接收者可用且有范围read；全部事项先审阅，驳回项不进入内容。expiresAt未来≤31天。保存接收人、范围、审阅内容快照及确认人；专家另生成briefing_item授权。

现有状态recorded_not_sent，只登记受控链接，不代表企业微信/短信已发。附件和原始数据不会因事项发布自动获得全场资格。readPublication重新核接收人、期限、撤回和事项权限。

表有revokedAt，但缺授权人员可操作的publication撤回API/UI（C-G07）。补齐原发布者/授权管理者当前share、不可变撤回理由和时间；普通角色也须失效，不能只撤专家resourceGrant。

remindOverdue当前只写briefing_reminders pending/standby，没有实际提醒送达。真实替班接收链待渠道接入；需同时补软件投递链而不是只让现场测试“等提醒”。

API：GET/POST/PATCH `/api/v1/briefings`；POST schedules、explanations、tasks、publications；GET `/api/v1/briefings/publications/{id}`。新撤回接口属于待实现，当前没有。

## 8. C05 图片复核与现场效果

### 8.1 自动处理和权限

queueReview只允许已有完整图片的cameraEvent，核record，保存eventId/assetId/SHA/modelVersion和稳定requestKey，排image.review。runImageReview复读SHA，独立CPU推理，结果只追加alert_events，不改告警状态、人工结论或认领时间。

YOLOS-tiny ONNX/q8修订`e2f9c7673f0fa61849efe2b56a0d7774779ebb9d`，本地CPU，阈值0.5，目标person/car/truck/bus/motorcycle/bicycle；sharp转RGB、方向校正、40百万像素上限。只处理图片，不做视频、身份识别或自动滤警。score是模型得分，不宣称校准后的真实概率。

| 状态 | 现有含义 | 待补 |
|---|---|---|
| queued | 等待独立模型 | 自动排队入口C-G09 |
| running | 正在推理 | 租约/账号再检查、中断持久恢复C-G01/C-G02 |
| complete | 输出结构有效，结果已追加 | 不代表现场精度达到标准 |
| failed | 自动复核未完成，继续人工判断 | 错误码和原件保留，不吞原告警 |

C-G02：image_reviews没有创建者authVersion检查；执行前后未核当前权限，排队后撤权仍读原件/写结果，已经隔离实验确认。补齐明确执行主体、授权版本、资源资格和租约检查，而不是删除人工告警。

C-G09：attachCameraImage和原件导入没有自动queueReview。目前需要手工POST复核。补齐在“图片完整关联”事务排唯一复核任务，失败重试不重复首次通知；无图/加密/失败/关闭分别显示，不虚报已复核。

### 8.2 样本、标签与统计

image_field_samples保存day/night/rain_fog、独立录像/现场依据、发生时间、预定目标、expectedTrigger及cameraTriggered/platformReceived/personReceived（可null）。事件/复核必须同设备/对象；未告警时段也记录，未知不是false。

人工标签person/vehicle/absent/unknown，另存labelledBy/time。现有允许创建者给自己的样本标注；同createdBy＋requestKey异内容重复也只返回already_recorded（C-G10），不能据此称独立盲标与幂等一致性已经保证。

当前按场景统计样本数、预期事件、未触发/未收到/人员未收到、未知环节和模型完成数。没有基于人工标签计算模型TP/FP/FN、precision/recall或误报漏报率。

补齐：异内容同ID冲突；标注者独立于采样与推理结论，来源可审核；分别计算摄像头触发、平台接收、人员送达及模型判断。指标先冻结目标映射和正负例定义，分母0或unknown/未完成时显示未验证；不能只统计已告警图片。

现场白天、夜间、雨雾样本量/通过阈值由负责人和技术员先登记，随后执行；目前所有场景仍为未完成现场效果验收。暂停模型/积压时真实采集与夜间电话须另做负载演练。

API：GET/POST `/api/v1/image-review`；POST/PATCH `/api/v1/image-review/samples`分别样本与标注。模型许可证和版本证据沿现有`docs/licenses/`保存。

## 9. C06 评测与费用核对

### 9.1 现有固定集能证明什么

`tests/evaluations/一期固定评测集.json`版本local-agriculture-synthetic-v1，6篇合成资料、6题、每题2轮；冻结语义/混合Recall@5最低5/6，越权/撤回泄露和任意工具执行为0。

tools/evaluate.ts实际比较keyword/vector/hybrid的Recall@5、Top1、向量/SQL耗时，并验证无权检索、撤回和任意SQL拒绝；逐轮文件保存datasetHash、embedding/prompt/retrieval版本，费用null并写原因。

数据文件里的boundaryCases是条目清单，不等于评测脚本执行了全部8类；来源冲突、缺测、预算和超时主要由独立工程测试验证，不能合并为真实文字模型答题质量通过。

历史6题结果Recall@5分别66.7%/100%/100%，Top1 66.7%/100%/83.3%。混合未在全部指标优于向量；不能从12次小样本推生产准确率、延迟或成本。

### 9.2 专业质量补齐

C-G12：还需可重复的专业问题/答案证据评测入口和逐条人工评分。覆盖有依据、无资料、撤回、无权、过期、冲突、缺测、超时、主备、提示词注入和任务边界。先签标准，再跑冻结集，不用看到失败后改阈值。

每题记录来源/有效范围、预期限制、模型/提示词/检索/数据版本、每段耗时、实际usage/价格快照、证据支持、必要限制保留和越权拒绝。文字表述可不同，事实与边界必须一致；失败样例保留，不能只存总平均。
