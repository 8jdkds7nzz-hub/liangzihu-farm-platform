# 二期2a操作体验详细设计

## 目标与用户路径

工人从工作台进入本人任务/待核事项与现场记录；技术员进入任务、告警、分析与简报；负责人查看当前授权事项；维护人员进入设备与维护；管理员进入身份、台账和运行；专家只进入明确分享的资料。菜单可见性帮助使用，后台当前授权继续决定能否读写。

## 需求

| 编号 | 行为 | 验收 |
|---|---|---|
| U01 | 桌面侧栏分组、当前位置、工作区标题；手机折叠菜单、44px以上操作目标、键盘焦点、跳至内容 | 桌面/390px/窄屏无整页横向溢出，菜单能打开关闭 |
| U02 | 工作台按当前权限显示待办/入口，空数据有具体下一步；不制造农场KPI | 不同角色/对象/撤权及专家事项隔离 |
| U03 | 通用列表搜索、排序、记录计数、空/加载/错误/重试状态，移动可读 | 搜索不请求越权数据，路径变化清除旧数据，重试有效 |
| U04 | 对象、设备、测点和人员字段可搜索名称后选择，提交稳定UUID；选择项按当前权限过滤 | 同名靠对象/编号区分；输入不存在ID由原业务接口拒绝 |
| U05 | 统一表单反馈；失败保留输入、提交时禁重复、成功清空、网络变化提示 | 不把本机输入或等待状态显示成保存成功 |
| U06 | 统一颜色、字号、间距、卡片和可访问焦点；页面文案以业务操作为主 | 现有页面/离线入口可用；密码登录设置、权限与控制边界保持 |

## 接口与文件

`GET /api/v1/workbench`返回按当前身份可读取的任务/告警/简报事项计数和少量待办，不读全场后在前端隐藏。专家使用resource_grants筛选。`GET /api/v1/references?kind=object|device|point|person&objectId=`供名称选择；person限管理员或具有当前派单/分享/配置资格的对象内人员，禁止普通人员枚举全场账号。最多200条并提示范围限制。无Cookie持久业务缓存。

共用组件放`src/components/platform/`；工作台服务在`src/modules/workbench/service.ts`，引用选择在`src/modules/identity/references.ts`。布局仍由服务端resolveSession保护；客户端不直读数据库。通用useApi在路径变更/失败时清旧值，AbortController/请求序号防迟到响应覆盖新范围。

## 异常和验证

登录过期显示重新登录，权限失效不保留旧列表。移动导航不阻挡业务表单、网页缩放及浏览器返回；减少动画偏好受支持。不把对象授权自动继承给子对象，不以导航角色替代后端动作授权。采用agri_test随机schema和合成人员验证，再跑一期验收。
