# 二期2A操作体验补充设计

本文件补足原详细设计的使用流程、接口与维护细节。对应已实现版本2ea8f04，属于2026-10-03对现有实现的补记，不追写为开发前已存在的文档。原设计继续保留；发生差异时以本文件列出的当前代码与限制核查。

## 一、使用者与入口

| 使用者 | 首屏工作 | 查询范围 | 不能据此推定 |
|---|---|---|---|
| 工人 | 本人被派发或认领的未结束任务、授权对象告警 | 当前read授权，任务另限本人 | 看见任务不等于已派单或已到场 |
| 技术员、负责人 | 授权对象任务、告警、待审简报 | 当前对象授权 | 角色不自动赋予全部场区权限 |
| 维护人员 | 设备、维护及相关告警入口 | 明确授权对象 | 不默认取得专业审核资格 |
| 管理员 | 身份、台账、运行 | 管理动作与业务读权限分别核验 | 管理员不冒充农事记录人 |
| 专家 | 明确分享的事项 | 对象授权与resource_grants交集 | 不允许浏览全场历史 |

访问路径为登录→工作台→具体事项→原业务页面。工作台仅提供入口及当前授权内待办，不创建新的业务状态。设备、对象、任务和记录页面继续使用原有操作链。

## 二、页面区域与操作

桌面侧栏按日常工作、空间资料、分析协作、管理分组；顶部显示当前位置及我的账号；页尾提供问题反馈。手机菜单默认关闭，使用按钮展开，背景遮罩可关闭，Escape关闭后焦点返回按钮。关闭的手机侧栏同时设置inert和aria-hidden，不能被键盘误入。

“跳至内容”链接定位工作区；当前导航使用aria-current。用户切换页面时关闭手机菜单。操作目标、正文和表单保留浏览器缩放能力，长表格使用容器滚动或移动标签，不制造整页横向滚动。

后台拒绝才是权限结论，菜单隐藏只是便捷呈现。页面无数据时提示登记与授权；加载中、读取失败、确实无记录分别呈现。

## 三、工作台接口契约

GET /api/v1/workbench 返回role、tasks、alerts、briefingsAwaitingReview、objectCount、limits、checkedAt。

| 字段 | 来源与排序 | 上限与含义 |
|---|---|---|
| tasks | field_tasks，排除reviewed/cancelled；due_at空值后置，然后created_at | 最多20条，工人另限assignee/claimed_by |
| alerts | alerts，排除closed；severe优先，再opened_at倒序 | 最多20条，不表示全量告警数 |
| briefingsAwaitingReview | briefing_items中decision=draft | 当前授权内数量 |
| objectCount | 当前read授权对象集合 | 不递归继承子对象 |
| checkedAt | 服务端生成 | 查询时点，不代替设备采样时间 |
| limits | 服务端固定范围说明 | 随响应展示，不隐藏截断事实 |

服务端分别调用visible处理task、alert、briefing_item；专家每种资源单独过滤。工作台不连接厂商、不调用模型，也不修改告警认领时钟。

## 四、引用名称选择契约

GET /api/v1/references 支持kind=object/device/point/person，可带objectId。返回items与limited；查询201条、交付前200条，超过时明确limited=true，不假称全量。

| 类别 | 标签内容 | 权限规则 |
|---|---|---|
| object | 名称、编号 | 当前read对象 |
| device | 名称、所属对象、厂家编号 | 设备所属对象read |
| point | 名称、所属对象、测点编号 | 经设备核所属对象 |
| person | 姓名、角色 | 管理员；或在有dispatch/share/configure且有read的对象内选择人员 |

普通工人不能枚举人员，专家不能借通用选择器枚举设备测点。同名项按编号和所属对象辨认。用户选择后提交隐藏UUID，后端再次检查具体业务动作权限；选项曾经可见不等于提交时仍有权限。

## 五、列表与表单状态

| 状态/动作 | 页面行为 | 数据处理 |
|---|---|---|
| 首次读取 | 加载提示 | 不显示“无记录” |
| 路径切换 | 清除上一路径数据 | 取消旧请求并增加请求序号 |
| 同路径刷新 | 保留成功表单所在界面，提示读取 | 迟到响应不得覆盖新请求 |
| 网络/接口失败 | 错误及重试 | 清除旧列表，避免把过期值当当前值 |
| 筛选/排序 | 当前已载入条数及匹配条数 | 本地操作，不跨越API授权 |
| 提交中 | 禁止再次点击 | 由具体接口requestKey保证幂等 |
| 提交失败 | 输入保留，说明未确认 | 不重置稳定提交标识 |
| 提交成功 | 显示已保存，清表单并刷新 | 服务端成功响应为准 |

ActionForm按显式numbers/times/jsonFields配置解析字段。未知数量的空输入不转换为0；普通表单本身不承担业务单位换算。失败重试不能把同一requestKey换成另一份业务内容，否则接口应返回冲突。

## 六、兼容与维护

共用组件位于src/components/platform；useApi保留原返回字段并增加loading。DataList兼容数组和带items的分页响应，若返回格式不符则显示错误。原离线field.html沿用既有加密草稿及同步机制。

不新增数据库迁移；工作台读取一期表。账号密码登录继续遵守IDENTITY_MFA_REQUIRED=0的本机选择，未改身份凭据。未来新增菜单时应核对桌面、手机、工人及专家集合，新增引用种类必须先增加后端权限规则。

## 七、验收、证据与退出条件

1. agri_test中建立两对象、工人、技术员、专家和管理员，验证未授权任务不出现。
2. 撤销read后工作台清空；专家无resource_grants时不能看全部任务。
3. 普通工人调用person选择接口得到403；技术员仅选择有授权关系的人员。
4. 桌面及390px手机实际展开/关闭菜单、使用反馈入口、检查横向溢出。
5. 模拟网络失败后确认错误与重试，不将旧数据继续展示为正常。
6. 运行一期浏览器回归，验证共用组件更新没有破坏原操作。
