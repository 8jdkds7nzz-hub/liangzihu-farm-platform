## 本项目的结构选择

可选写法有三种：按模块逐项罗列适合查阅，但首次阅读较难形成产品印象；按开发期次介绍有利于审计，但容易把产品首页写成进度日志；按业务场景介绍更适合本次用途。

因此首页采用“项目定位 → 使用者与场景 → 功能 → 进度 → 启动 → 接入条件 → 技术与证据 → 文档与协作”。保留分期表作为交付入口，将完整运行说明移到 `docs/help/本地开发与运行.md`，既有设计和验收记录继续由 `docs/README.md` 导航。

| 读者需要回答的问题 | README 的对应内容 |
|---|---|
| 这是什么，解决什么问题？ | 开篇定位、为什么做、使用者 |
| 能用它完成哪些工作？ | 监测异常、现场作业、批次交付三条流程与能力表 |
| 软件长什么样？ | 已有浏览器验收截图，注明合成数据及来源 |
| 做到哪里，还有什么没做？ | 九个分段状态、G15 未实现适配、现场交接及四期范围 |
| 怎样在新电脑启动？ | 克隆、依赖、初始化、登录、后台进程和运行指南 |
| 用什么技术，如何验证？ | 技术层次、目录、带日期的交付测试与恢复证据 |
| 去哪里看细节或反馈？ | 总体设计、分段交付、岗位操作卡、Issues 与许可说明 |

## 事实依据与表达约束

- 功能表以 `src/app` 页面、`src/modules` 实现和各期交付记录为依据；[功能总清单](../baseline/智慧农业平台功能总清单.md)还包含未来范围，不能直接当已实现列表。
- 分期状态使用[一期](../releases/2026-10-02-一期软件补齐交付核对.md)、[二期](../releases/2026-10-03-二期软件交付核对.md)、[三期](../releases/2026-10-03-三期软件交付核对.md)交付记录；明确真实控制适配器尚未实现。
- 222 个用例、164 张应用表和 39 张非空新表均标注为既有交付快照，不冒充本次 README 修改新增的测试成绩。
- 快速启动逐项核对 `package.json`、初始化脚本和 Compose 配置。Docker 只承担当前数据库服务，不宣传不存在的一键整套部署。
- 保留新环境默认二次验证与原开发机密码登录设置的区别，不公开任何实际凭据。
- 使用现有合成验收截图，不展示实际人员、农场私有文件或未经核实的田间成果。
- 仓库为私有项目，未声明项目级开源许可证；不添加开源、生产可用或 CI 通过徽章，不承诺未经测量的部署时间、容量和模型准确率。

## 文档验证方法

检查本次文档的相对链接、图片、章节锚点、脚本名称和源文件路径；渲染首页核对桌面与手机布局。按仓库规则在独立工作副本检查类型和构建，避免覆盖正在运行的主目录构建。

本次验收对象是文档的准确性、可读性和可导航性。历史验收证据保持原样，现场接入状态不因首页改写而改变。
