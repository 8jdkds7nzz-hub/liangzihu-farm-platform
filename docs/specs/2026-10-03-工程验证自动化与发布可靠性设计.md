# 工程验证自动化与发布可靠性设计

用户已授权按建议顺序全部执行。本轮覆盖Q01补强、Q02、验收诊断与需求对照、Q04和Q11的工程交付；其他产品页面功能仍按原Q计划推进。基线为5100718，业务改动仅限故障用例实际复现的缺陷；迁移、账号与现场外部开关保留。

## S1 检查器与环境

同一副本同时只允许一轮检查；锁带进程和随机所有者标识，未释放的锁不擅自删除。报告使用临时文件加原子重命名，逐步登记running与耗时；初始化失败、中断和源码变化都不能生成通过结论。检查前后按相同文件集记录源码及锁文件摘要，忽略可再生缓存。

保留quick与delivery，增加core：单元、构建、无模型依赖的核心数据库/浏览器链。core通过只代表该明确子集；delivery仍完整执行。测试文件缺失或零用例拒绝，不让Node隐式发现其他套件。失败重跑建立新运行记录，关联原运行号并保存首次失败；后续成功标作不稳定线索，不覆盖第一次结果。

非quick检查必须使用仅有测试配置的副本，拒绝Next会读取的开发/生产环境文件。新测试环境由专用脚本创建独立、带所有权标记的Docker容器，只建agri_test和非超级用户agri_tester，随机端口与凭据留在忽略目录。环境核对检查实际库名、角色、权限和实例标记；恢复工具必须核对同一容器标记及连接端口，不能借名字猜目标。既有本机数据库初始化脚本不变。

## S2 自动回归与可复现环境

GitHub Actions对代码提交/PR运行core，完整delivery可手动运行。固定Node、pnpm及动作版本；fetch-depth为0以支持旧版本兼容。只上传白名单公开摘要，不上传私有日志、环境、转储及截图。运行时生成的测试凭据不进仓库。不设置分支保护、不部署生产、不购买付费资源。

本地以全新测试配置和独立数据库完成工程验证；远端Linux运行记录单独保留URL、提交与实际结果。模型准备是delivery的显式前置，不以缺模型为理由把完整检查标通过。模型缓存只存可再生文件。

## S3 失败定位、需求对照与摘要

私有报告记录失败用例名、日志位置、复现步骤及重跑关联；公开摘要仅保留固定步骤ID、状态、数量、耗时、提交/摘要及固定错误代号。诊断不把任意业务内容转入公开报告。

对照现有1A—4C的逐项验收文档，检查代码、测试、证据和相对链接。历史哈希按其历史提交解释，当前文件变更不改写旧证据；执行范围、已映射测试文件和未纳入本次检查的项分别展示。文件存在/测试文件执行不等于每条需求已获得独立断言，更不关闭G01—G18。

## S4 升级回退、容量与故障

发布清单绑定确切提交、代码摘要、锁文件、迁移及已通过的完整运行记录。版本变化、源码变化、迁移漂移或非完整验收拒绝生成“可交付”清单。

升级演练在agri_test随机schema与独立旧/新构建中执行：旧版真实身份和业务数据→故意失败迁移及事务回滚→真实新迁移→新版本读取→旧应用读取新结构的兼容回退。保留新增数据，不能删表冒充回退。需要时恢复本轮私有副本，目标始终是自身测试schema。实际云端切换仍依赖G06/Q03部署环境。

容量验证使用250与5001条合成库存记录、100项任务及并发操作，记录列表既有200条上限和5000条导出边界；不扩展尚未实施的Q09分页。持续运行窗口预先固定10分钟，采样至少30次，记录P50/P95、队列、进程内存和连接。工程阈值：单次操作30秒内结束、队列最终归零、完成任务/业务分录不重复；资源趋势作为测量不宣称全场容量。

故障注入包括测试worker被终止后租约恢复、过期令牌拒绝、隔离数据库连接中断后重连、下载中断/重试、备份失败。只影响自建资源，不终止或暂停现有开发/生产数据库。真实生产RPO/RTO继续待G06，10分钟工程窗口不冒充长期现场稳定性。

实际故障补修：目标存储在消费输入前失败时，调用方原先可能留下未关闭的文件流。先用关闭状态断言复现，再在媒体模块的三个流式写入入口共用关闭处理，保持原有校验、权限、重试及错误语义。CPU推理安装按已锁定onnxruntime-node提供的skip开关跳过未使用的CUDA下载，不改变模型或业务计算。

每部分都有源代码、针对性反例、实测记录和使用说明。修改检查器后运行快检、core和完整delivery；运行四组恢复、升级回退、10分钟稳定性及远端LinuxCI。源代码、历史验收与主目录用户改动在合并时逐项核对；公开交付只用脱敏摘要。
