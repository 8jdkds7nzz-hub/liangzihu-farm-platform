# 三期3A字段接口与操作约束

本文件与3A详细设计共同构成实施后的完整规格。对应src/modules/inventory和迁移035；用于工程接手、验收和后续接口对接。请求中的UUID应从当前授权台账选择，不能把文档示例当作真实农场记录。

## 一、共同请求和应答

写接口为POST /api/v1/inventory/{section}，Cookie登录、同源Origin、JSON。请求上限256KiB；每笔写入在同一个数据库连接和事务内完成。

所有写动作带requestKey；浏览器在同一表单失败重试时保留此键。相同主体、同操作、同键、同内容返回原提交结果；同键改内容返回REQUEST_KEY_CONFLICT。页面刷新或新开表单是新提交，操作前应查看现有单据，不能靠相同备注推定重复。

幂等信息统一存inventory_requests：object_id、created_by、kind、request_key、input_hash、result和created_at。stock_documents本身保存业务单据，不重复保存request_key。库存、质量、植保、农情等写操作均用这个事务内请求记录；domain_events同时留业务事件。

## 二、数量契约

| 输入 | 处理 |
|---|---|
| 十进制字符串或有限number | 规范化为最多六位小数的十进制字符串 |
| 单次数量上限 | 1,000,000,000 |
| 件数 | 只允许整数 |
| null、空字符串、undefined | 作为未知时保留空；需要过账时拒绝 |
| 0 | 可明确记录计量零；库存过账数量必须大于0 |
| 负数、科学计数法字符串、NaN、Infinity、超过六位小数 | 拒绝 |
| 数据库存量 | numeric(20,6)，由分录求和；内部加减使用BigInt微单位 |

unit固定kg、L、piece；basis固定as_is、wet、dry，非kg只能as_is。六位小数是存储/计算格式，不代表仪器有六位测量精度。毛重和净重字段单位kg，count为件数，moisture为0—100百分比；均可未知。库存在不同unit或basis间不自动换算。

## 三、登记接口

| section | 必需字段 | 可选字段 | 结果 |
|---|---|---|---|
| locations | objectId、code、name、requestKey | expectedActorId | 仓位id及所属对象 |
| lots | objectId、code、product、kind、unit、basis、source、requestKey | productionBatchId、identities、expectedActorId | 待检批次id、version=1 |
| purchases | lotId、supplier、voucher、quantity、occurredAt、requestKey | expectedActorId | 采购凭证记录，不改变库存 |
| applications | lotId、issueDocumentId、quantity、occurredAt、evidence、requestKey | farmRecordId、expectedActorId | 实际施用记录，不再次扣减库存 |

identities是regulatory、inventory、logistics、supplier四类字段；不明的为null。inventory若填写必须等于code。生产批次必须已存在且同对象。kind为input/harvest/processed；本期不扩展四期循环物料类型。

## 四、库存动作接口

movements共同字段为objectId、kind、occurredAt、evidence、requestKey。

| kind | 追加字段 | 权限/限制 |
|---|---|---|
| receipt | lotId、locationId、quantity | 新收到货须待检批次 |
| harvest | 同receipt | lot.kind必须harvest且待检 |
| issue | lotId、locationId、quantity | 当前质量依据有效且余额足额 |
| transfer | 以上及toLocationId | 两个不同仓位，同对象同批次 |
| return | lotId、locationId、quantity、direction=in/out | 入方向须待检批次；退货事实不自动修改质量状态 |
| downgrade | lotId、targetLotId、locationId、quantity、reason | review权限，同单位口径，转为有谱系的转换单 |
| adjust | lotId、locationId、quantity、direction、reason | review权限，记录差额，不写最终余额 |
| reverse | reversesId、reason或evidence | review权限，只冲销一次，无下游依赖且不造成负库存 |

普通记录仍需read+record；管理员角色不自动具备农事记录动作。所有涉及批次按ID排序锁定，再查余额与过账。不同对象仓位拒绝STOCK_SCOPE；同仓调拨拒绝STOCK_TRANSFER_SAME。

## 五、加工接口

transformations必需objectId、code、kind=processing/downgrade、inputs、outputs、occurredAt、evidence、requestKey；差异时还须reason及review权限。

每边1—20行，行结构：
```json
{"lotId":"所选批次ID","locationId":"所选仓位ID","quantity":"10"}
```

同一步不重复输入/输出同一批次。输入需有效放行、余额足够，输出须pending。对同对象谱系串行检查后建立stock_lineage，禁止形成循环。相同code表示同一长期转换，kind不能变；每步单据仍独立。

只有单位和basis都一致才给difference；不一致返回comparable=false、difference=null，并保留计量解释。数量比较不是未申报投入的证明；真实物料平衡和损耗需现场核账。任何行失败整笔回滚。

## 六、包装与交接接口

packages：objectId、code、lotId、action=add/remove、quantity、occurredAt、evidence、requestKey。装拆包装为物流身份关系，不当作库存增减或库存预留。拆出不得超过该包该批累计装入量。

handoffs发货：direction=dispatch、lotId、locationId、party、quantity、occurredAt、evidence、requestKey；扣减当前已放行库存。收货：direction=receipt、dispatchId、party、quantity、occurredAt、evidence、requestKey；不自动给另一对象入库。分次收货累计不得超发，少收量由dispatchStatus保留outstanding。

## 七、查询、导出和分享

- GET overview?objectId：当前对象每类最近200条，余额按批次/仓位汇总，最多200组。页面筛选/排序只针对已载入集合。
- GET lot?id：指定批次及最近200条分录，专家须该批次事项授权。
- POST export，body含objectId：要求read+export，返回phase3-stock-v1，每表最多5000条、总量8MiB；超限明确拒绝，完整历史由管理员备份保留。
- 专家分享固定stock_lot；/inventory/lots/{id}可查看。撤回从分享记录选择，不靠删除业务记录。
- 跨对象调拨、全库无限搜索、成本核算和供应商ERP联机不属于当前实现；页面明确载入上限，不冒充完整全季列表。

## 八、常见失败及处理

| 错误 | 处理 |
|---|---|
| LOT_NOT_RELEASED / QUALITY_NOT_CURRENT | 到质量页核对报告、期限和未结问题，不能重复提交绕过 |
| INSUFFICIENT_STOCK | 核对仓位和现有分录；并发只允许实际可用量过账 |
| STOCK_DIFFERENCE_REASON | 补计量/损耗依据并由具review人员处理 |
| STOCK_DEPENDENCIES | 原单已有施用、转换或交接，先追查和处置依赖 |
| APPLICATION_EXCEEDS_ISSUE | 核对已分配施用量，不能把再次施用当作再次领用 |
| RECEIPT_EXCEEDS_DISPATCH | 核对分次签收与原发货，不覆盖旧数量 |
| REQUEST_KEY_CONFLICT | 保留原草稿，核对原提交与新的业务意图 |

对应执行记录A31—A36；本机工程数据均为合成，真实仓位和单据按G13核验。
