# 三期3B字段接口与审核约束

本文件展开3B详细设计的接口、数据、状态和接手方法。实现位于src/modules/traceability，迁移036；页面/traceability，客户页/trace/{code}。所有状态以当前服务校验为准，不能直接改库将批次设为available。

## 一、共同机制

内部POST /api/v1/traceability/{section}使用已有Cookie/Origin/JSON限制，上限256KiB，稳定requestKey和同连接事务。未知section返回404，不能借对象原型属性调用其他函数。

样品、报告、凭证、决策、查询和案件事件追加留痕。用户看到的“审核状态”与“当前可用性”分开：旧放行仍可追溯，但报告过期、新失败或未结问题会阻断实际领用、加工输入、发货及客户查询。

## 二、样品与报告

| 接口 | 字段 | 核对 |
|---|---|---|
| samples | lotId、sampleCode、stage、sampledAt、source | 同对象样品号唯一，raw/finished分开 |
| tests | sampleId、method、result、reportRef、testedAt、validUntil | 检测不早于采样；有效截止晚于检测；结果pass/fail/inconclusive |
| tests更正 | 以上及supersedesId | 必须同一样品、不能分叉更正、时间不早于原报告 |
| credentials | lotId、kind、subject、product、validFrom、validUntil、evidence、verified | certificate/certification/brand；verified=true要求review权限 |

当前检测指未被后续更正的报告。质量放行引用的报告须为正确阶段的pass、当前有效；同批另有未更正的fail或inconclusive仍阻断，不得只挑一张通过报告。产品为processed时要求finished，其余要求raw。

报告和凭证字段存可追查的文号/依据；原件可在私有媒体库保存并另授权限。软件没有自动核验行政证书真伪或联网查询认证数据库。

## 三、放行事务

POST decisions：lotId、expectedVersion、toState、testIds、credentialIds、evidence、requestKey。UUID数组各最多20项且不重复。

1. 核当前批次read和review权限，锁定批次。
2. 检查expectedVersion；旧版本报QUALITY_VERSION，不静默覆盖。
3. toState为available时，审核人不能等于批次创建者。
4. 检查所选测试、所有未更正失败、未结问题及引用凭证。
5. 追加quality_decisions，version增加1，再更新当前state。

可明确决定pending、blocked、returned或recalled并保留原因；不能因为一个采购/退货/通知动作就自动推断质量状态。放行是专业人员根据资料作出的记录，不是软件自动质量认证。

## 四、正反向追查

POST queries：lotId、direction=forward/backward、requestKey。图从stock_lineage遍历，固定最大20层、500节点；每层最多2000条关系，包装及交接各最多2000条。

snapshot包括nodes、edges、packages、handoffs、boundary、truncated、complete=false和limitations。没有关系不等于不存在供应链历史，因此不输出无依据的“全链完整”。遇到未授权节点只给边界提示，不透露其内部ID、名称或数量。

同主体/根批/方向递增version，快照以SHA固定。GET query?id重查每个节点当前权限；撤权后拒绝读取旧快照。POST query-export含queryId，额外核每个节点export动作，返回phase3-trace-v1。读取权限不自动赋予正式批量导出权限。

## 五、质量案件

| 接口 | 字段与状态 |
|---|---|
| cases | lotId、title、targetQuantity、evidence、requestKey；初始open |
| case-events notice | caseId、occurredAt、evidence；登记实际人工通知凭证 |
| case-events recover | 以上及quantity；累计不超影响量 |
| case-events dispose | 以上及quantity；累计不超已追回量 |
| case-events close | require review；通知、追回和处置均齐才closed |

targetQuantity按批次单位，未知必须先核实，不使用0伪装已完成。每步保留人员和时刻；未追回/未处置持续显示剩余量。结案不自动改变批次质量状态。平台不代替人员发送真实召回通知。

## 六、客户页面草稿

POST cards：lotId、content、credentialIds、validUntil、requestKey。有效期在未来一年内。content只能使用下列字段：

| 字段 | 内容与限制 |
|---|---|
| productName | 与批次品名一致 |
| batchLabel | 独立公开标签，不等于内部库存/供应方等批号 |
| province/city/county | 省市县，不能含数字地址和坐标 |
| harvestMonth | YYYY-MM |
| productionSummary | 经审核的生产摘要 |
| testSummary | 经审核的检测摘要 |
| limitations | 查询范围、资料缺口和适用限制 |

服务端另加granularity=批次级。拒绝额外字段、UUID、原件HTTP链接、可识别坐标对、个人手机和邮箱；这些检查不能代替人工审稿。不存在一个把内部完整JSON直接公开的接口。

随机访问码为24字节随机数的48位十六进制，独立于内部UUID。草稿默认不可公开；固定版本保存内容，不随内部档案编辑自动扩张。

## 七、客户审核与撤回

POST card-review：id、action=approve/revoke、evidence、requestKey。要求review+share，批准时不能自审，且批次当前质量与选中凭证有效。

GET /api/v1/public/trace/{code}匿名读取，只返回公开content、version、reviewedAt、validUntil、checkedAt。每次重核状态、到期、质量和凭证；无效统一404。响应no-store、no-referrer、noindex/nofollow。页面只渲染白名单，不泄露object_id、lot_id、私有媒体键和仓位。

撤回后新请求立即拒绝，但不能承诺收回已保存截图。页面审核与撤回结果还保留在不可变提交记录中，当前卡片状态不是唯一历史依据。

## 八、验收与交接

独立审核、版本冲突、报告失效、未结案件、正反向关系、专家边界、页面白名单与撤回有数据库断言；浏览器实际用第二个账号批准页面并匿名读取，再撤回验证404。恢复演练重新检查这些限制没有被清空。

B31—B36记录各项路径与证据。真实报告真伪、资质、召回凭证和客户展示内容待G13；没有把本地合成测试当作真实合格证明。
