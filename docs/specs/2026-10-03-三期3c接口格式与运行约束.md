# 三期3C接口格式与运行约束

本文件补充3C详细设计的可执行契约、限额与运行方式，便于接手而不是只看功能标题。对应037、038迁移以及protection/agronomy/control模块。

## 一、入口与共同规则

| 页面 | API前缀 | 主要动作 |
|---|---|---|
| /protection | /api/v1/protection | plans、prescriptions、prescription-review、prescription-events、executions、imports、deliveries、followups |
| /agronomy | /api/v1/agronomy | crops、labels、spectral、schedules、schedule-toggle、notices、notice-review、flows |
| /control-records | /api/v1/control-records | profiles、rules、rule-review、requests、feedback、takeovers |

均使用同源Cookie、Origin、JSON和稳定requestKey。protection请求2MiB、agronomy请求256KiB、control请求32KiB；导入rows本身另限1MiB/100行。列表每类最多100条，原件选择最多200项。

## 二、植保计划数据

plans必填objectId、title、crop、target、stage、boundary、obstacles、sensitiveNote、conditions、inputLotId、source；可选taskId、supersedesId、sensitiveAreas。

boundary为WGS84 Polygon/MultiPolygon，使用PostGIS检查有效性；障碍是明确文字位置说明。敏感邻区每项有name、kind、geometry，最多30项；空列表还必须解释核实情况。存在图形不自动等于测绘已通过。

同对象投入品和任务必须已存在。原版本通过supersedesId连接，旧记录不可改；后续专家分享按明确版本授予。

## 三、处方契约

prescriptions必填planId、zones、doseUnit、basis；可选sourceAssetId、sourceAnalysisId。zones每项name、rate、geometry，共1—5层，须位于计划内且无正面积重叠；rate非负，未知不可填0。

doseUnit为kg/亩、L/亩、g/亩、mL/亩。软件保存专业人员提供的数值，不从指数自动算药量。来源影像须完整同对象，来源指数须已计算完成。

prescription-review为id、action=approve/withdraw、evidence。批准须其他审核人员；分享/下载/施用事实另走prescription-events，字段prescriptionId、action=shared/downloaded/applied、party、occurredAt、evidence；applied须executionId匹配。

专家看计划不代表获得所有后来处方。protection_plan与prescription_map分别授予；处方详情地址/protection/prescriptions/{id}。原件依然需要自己的media授权。

## 四、实际作业格式

executions必填planId、operator、startedAt、endedAt、unit、evidence。其余字段：

| 字段 | 语义 |
|---|---|
| prescriptionId | 如引用，须同计划且在作业开始前已批准 |
| track | 最多1000点；每点time、longitude、latitude、spraying、flow、flowUnit |
| swathM | 已核喷幅，0—100米范围内且必须大于0；未知留空 |
| maxGapSeconds | 已核连续条件，1—3600秒；未知留空 |
| materialQuantity | 实际自报材耗，可空；unit须与投入品一致 |
| resultCheck | 已有复查说明，可空 |
| remediationOf/cause/remediationCost | 同计划原作业、data_equipment/environment/organization、CNY费用可空 |

轨迹时间先规范化为带时区的ISO格式。相同时刻重复拒绝，不能因不同文本格式误判先后。经纬度成对，启停true/false/null，流量非负或null。

仅坐标齐、两端均喷施、流量为正且时间间隔满足条件时组成连续段。最多500有效段；超限需拆分。按喷幅在geography米制缓冲，计算疑似覆盖、漏作及非相邻段重叠，保存定位几何。缺信息时返回null面积和具体gap，不能判100%完成。材耗自报不自动再次扣库存，须与3A实际施用记录核账。

## 五、离线JSON导入

imports为objectId、sourceRef、rows、requestKey。sourceRef是稳定设备/服务商来源；每行包含externalId和上述execution字段。原字段值及规范化输入SHA保存在protection_imports，不把该SHA冒充未上传厂家原始文件的字节SHA。

返回rows：row、ok、成功id或失败code/message。每行SAVEPOINT，错误行不回滚其他成功行。同来源externalId重试复用原执行，改内容冲突。原厂家文件和照片可先入私有媒体库，再通过交付清单关联；平台不猜未提供的厂家专有CSV列名。

这里的离线是导入设备离线文件，提交仍需联网。手机农事断网草稿继续使用一期/field.html；库存和处方不在断网时伪装已过账。

## 六、交付与复查

deliveries：planId、provider、kind、assetIds、missing、receivedBy、occurredAt、evidence。kind包括raw_images/processed/work_order/track/arrival/followup；附件必须完整同对象，最多100项。

followups：executionId、observation、judgment、action、occurredAt、evidence。观察、判断、后续动作分开；未记录不得写已复查。所有这些事实是内部记录，不能替代服务商签字或真实到场证明。

## 七、照片分析运行

crops：assetId、可选flightId、evaluationMode。首版接收PNG/JPEG/WebP RGB照片，最大20MiB、解码最多4000万像素，分析图缩至最长边1024。计算绿色像素、暗像素和过曝比例，保留原尺寸、分析尺寸及方法版本。

候选模型选SigLIP2 ONNX q8，固定修订ba1f3b0843f24bc5417d38e19c37b287d719b2f4；标签与模板固定。转换版tokenizer具有超大占位长度，实测会导致Invalid array length；本实现依据[官方SigLIP2文本预处理](https://github.com/huggingface/transformers/blob/main/docs/source/en/model_doc/siglip2.md)固定64 tokens，未改第三方缓存文件。

CROP_MODEL_EVALUATION_ENABLED默认0；RGB特征可独立运行。开启实验仍返回agronomicValidation=not_validated，分数不是农业概率。人工labels追加保存，与模型结果不互相覆盖；当前最近100条中独立标注一致性仅供工程复盘，不能当现场准确率。

## 八、多光谱计算运行

spectral：assetId、rawAssetIds、capturedAt、sourceRef、processor、indexKind、bands、calibration、breaks，可选flightId。

- indexKind为NDVI/NDRE；bands按0起始填red/nir或redEdge/nir。
- calibration包含state=reflectance、scale、offset、evidence；首版同一比例/偏移，其他校正须上游处理。
- breaks严格递增、位于-1与1之间，最多4个，产生最多5类。
- 原件64MiB/400万像素，北向WGS84 PixelIsArea；旋转/其他投影、缺波段或校正拒绝。
- 每用户最多5个待计算产品；rawAssetIds不能是本产品自己或已标记的派生成果。
- 零分母、无效值和反射率越界不计有效像素；没有独立云/阴影掩膜时保留限制。
- 输出私有Float32指数GeoTIFF与分类PNG，明确-9999无效值，输入SHA、版本和参数固定。

解码在受限子进程，120秒超时，512MiB Node堆上限。输出原件写入失败时任务可失败/重试，后台对账避免永远显示运行中；派生文件ID按任务和用途确定，重复完成不新增一组输出。

## 九、调度、通知、流量

schedules保存已核只读摄像设备、intervalMinutes=15—10080、enabled、nextAt、evaluationMode、sourceRef。按窗口防重，后台最多每30秒扫描一次；全局CAMERA_READS_ENABLED=0时记录blocked，不请求厂家。抓拍结果未知时不盲目重试，取得完整原件后再排分析任务。

notices记录agency、sourceRef、publishedAt、validFrom/until、crop、region、body及可选supersedesId；其他review人员确认后才可作为当前信息，撤回/过期/被新版本替代保留历史。

flows记录objectId、可选deviceId/pointId、fromAt/toAt、value可空、unit=m3/s或m3、sourceKind、basisRef、basisVersion、applicability、validUntil。率定/模型来源要求review权限；没有任何开度自动转水量公式。

## 十、控制与真实缺口

profiles：设备版本、permission、mode、protection三态、负载和断网/停电/复电行为、协议与反馈依据、复核截止。rules保存用途、物种、阶段、条件及专业审核。requests只保存目的、授权和现场条件，state恒为blocked、dispatched恒为false。

feedback分request/device_received/electrical/mechanical/effect。只有平台自身登记能够形成request层；其他层必须注明vendor_receipt或field_observation，unknown值保存null，不能假称平台发过命令。takeovers记录真实到场人、装置、条件和时间。

**真实执行适配器尚未实现，属于G15外部资料依赖开发项。** 供应商核对文件仍缺寄存器、协议实例、反馈含义和平台权限。不是填写一个开关就能控制；取得资料后须按具体设备另行编码、测试并联合签验。闸门依旧独立插入接入。

## 十一、后台与故障

运行worker:agronomy，复用任务租约和当前主体authVersion；作业前后核原件/对象权限。失效主体不能提交结果，失效租约不能完成。模型准备使用models:crop-prepare；正常推理禁止远程下载及图片外传。

只对当前已实现路径登记工程通过。真实库存/质量G13、植保/模型/多光谱G14、设备执行G15均另行列明；不把39张新表非空恢复当作真实农业效果或生产灾备认证。


流量原数值和单位分别保存；只有已登记且两端一致的L/min、L/s、mL/s、kg/min、g/s或kg/s用于正流量连续判断。未知/其他单位保持缺口，不积分、不默换单位。
