# 四期范围与开源产品借鉴

日期：2026-10-03。基于 `6f85e10`，按用户已授权的规划、设计、执行、测试流程推进。四期范围沿用 baseline 第12、13节，不把尚未完成的 G01—G15 现场条件记为已完成。

## 范围与分段

| 分段 | 基线模块 | 交付目标 |
|---|---|---|
| 4A 能源与循环物料 | M7、M12 | 设备能源资料、来源明确的观测与区间统计；循环物料接收称量、处理、筛分返料、检测与去向，复用三期库存 |
| 4B 农机服务与费用补贴 | M13、M15、M17 | 北斗资料接入条件、机具终端绑定、人工派单、轨迹与业务证据验收；费用、付款事实及三类补贴分账 |
| 4C 科研试验与综合指标 | M8、M16、M18 | 试验小区、基线/对照、观察与检测计划、成果证据、经费关联；按对象和时段核查设备、作业、质量、调度、经营、服务、风险 |

沿用一个 Next.js 应用、PostgreSQL/PostGIS 数据库和现有角色、对象、私有文件、审核、导出、事件与请求幂等设施。不安装第二套 ERP、物联网平台或科研平台。

## 本轮前置复核

R41：二期共用表单在三期部分导入失败时重置输入；R42：账号切换保护只覆盖三期表单；R43：历史 B07/C07 记录缺少显著的当前进度导航。R44：三期植保文件跨账号导入时，原来只有账号内防重，现补来源外部号全局身份及历史冲突提示。按[复核补齐计划](../plans/2026-10-03-一至三期复核与补齐计划.md)先复现并补齐。

## 从真实 Issue 转为验收条件

Issue 是报告者的具体场景，不自动代表所有版本都存在问题。下列借鉴不依赖其最终修复状态。

| 原始反馈 | 本项目要避免的问题 | 对应验收 |
|---|---|---|
| [Frappe #38755](https://github.com/frappe/frappe/issues/38755)，2025-08-07：分页读取库存时报告重复与漏记录 | 用界面最近200条冒充完整统计或完整导出 | 管理汇总从数据库按范围计算；导出有明确上限，超限拒绝而不是静默截断 |
| [Metabase #65713](https://github.com/metabase/metabase/issues/65713)，2025-11-11：升级后筛选值读取报500、控件表现变化 | 只测后端成功，不测筛选、空值和升级后的真实页面 | 二、三期页面回归，四期测试下拉、空数据、失败保留输入及手机布局 |
| [MLflow #25313](https://github.com/mlflow/mlflow/issues/25313)，2026-08-24：评测集修改后缺少可重新取得的历史版本 | 只存哈希却无法复查当时的输入数据 | 试验结果和管理报告保存实际输入引用及可读取快照；修改观测追加新版本，旧结果仍可回读 |

沿用已有 RAG 和模型评测链，本轮不增加无验证用途的 Agent 自动决策。用户列出的 `AI-Product-Basics`、`Product-Management-Open-Source` 未提供唯一所有者地址，本次不猜测仓库归属或将同名搜索结果当权威来源；已经核实的项目足以支持本轮设计。

## 共用约束

- 数量使用既有六位定点，金额仅人民币、最多两位小数；未知留空，不用0占位。不同单位和鲜干基不直接相加。
- 写操作按当前会话、角色和对象授权校验；业务记录带稳定请求键、原账号、来源和发生时间，审核人独立于创建人。
- 只追加 `039—043` 迁移，不改已应用 `000—038`。不填虚构开发库数据，不修改用户密码或已选择的登录设置。
- 原记录保留；修改用后继版本或冲销，审核结果不能绕过新的失败、失效或撤回依据。
- 业务导出按当前对象及 export 权限，表级最多5000行、8MiB；超限明确拒绝。图片及附件仍经私有媒体入口重新鉴权。
- UI沿用二期布局、名称选择和加载/失败状态，三期的对象工作区、稳定提交与可撤回分享；展示数量上限不充当计算范围。
- 真实支付、政府申报、厂家读取、通知发送和设备控制不因四期功能上线自动执行。缺协议不编造 HTTP 或寄存器适配。
- 每段测试使用 agri_test 随机schema；所有新增表以非空数据做实际备份恢复。旧验收证据保持原字节，新回归放独立目录。
