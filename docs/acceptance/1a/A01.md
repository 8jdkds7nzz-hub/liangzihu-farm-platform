# A01 账号、二次验证与对象权限验收

验证日期：2026年10月1日。**程序与本地验收完成；企业微信真实登录仍受G03阻塞，未验收生产接入。** 当前开发入口为`http://127.0.0.1:3100/login`。

## 已实现

- 本地账号密码登录、退出、我的账号页面；六类角色及对象和动作授权。
- 密码采用随机盐的scrypt散列。随机会话令牌仅在Cookie中传递，数据库只存SHA-256散列；不接受浏览器传入的角色，也不把集成令牌当作人员会话。
- 管理员、有configure/act授权者及已经绑定验证器的账号必须二次验证。第一步只发5分钟挑战，验证成功后才发8小时完整会话；挑战不能调用业务或管理接口。
- TOTP使用锁定的otplib 13.5.0；采用30秒周期、前后30秒容差，成功步数落库防重放。AES-256-GCM加密secret，并以用户ID作为附加认证数据，不能换用户解密。8个随机恢复码仅显示一次、数据库只存散列，并发使用只能成功一次，使用留审计。
- 密码和二次验证分别按账号持久限流：15分钟窗口内5次失败后锁15分钟。新建挑战不能绕过MFA失败限制。对未知账号使用同等密码散列计算和相同失败提示。
- 每次请求重新查账号和授权，无跨请求权限缓存。停用、角色或密码变化使旧会话失效；停用再启用也不能恢复旧会话。新增配置或动作权限后，原有普通会话必须重新登录并完成MFA。
- 管理员的人员配置权限不自动产生业务查看权。所有业务对象仍须明确授权；查看、记录、审核、导出等动作分别判断，范围内列表使用同一个授权入口。
- 接入凭据只允许单个对象的read或record，必须有到期时间；支持撤回，不提供全局共享令牌。管理员签发留审计，签发账号停用时一起撤回。
- 写接口验证配置中的确切Origin；忽略Host和转发头对授权地址的影响。JSON请求体限制8KB，错误响应不暴露数据库或密钥信息。认证响应禁止缓存，Cookie为HttpOnly、SameSite=Lax；配置HTTPS域名后带Secure。HTTP仅允许localhost/127.0.0.1本地入口。

会话8小时、挑战5分钟、失败5次和锁15分钟是本轮实现参数，试运行前可依据现场使用情况复核，不是厂家指标。

## 本机使用

执行`pnpm identity:setup`后，初始账号凭据位于仓库内`.local/初始管理员凭据.json`。文件权限0600，已被Git忽略；密码未打印、未提交。初始管理员没有业务对象授权，尚未绑定验证器。

1. 打开本机`/login`，使用私有凭据文件中的账号和密码。
2. 在自己的验证器中添加“基于时间”的账号，填入页面给出的密钥，再输入6位验证码。
3. 将8个恢复码保存到自己的密码管理器，进入“我的账号”。绑定密钥和恢复码不得作为截图或验收附件上传。
4. 保存初始密码后删除本机明文凭据文件；重复执行初始化脚本不会重置已有账号或重新显示密码。

`IDENTITY_ENCRYPTION_KEY`单独保存在`.env.local`，不能仅备份数据库而遗漏此密钥。已有加密资料却缺少密钥时，初始化脚本拒绝生成替代密钥。正式部署的密钥托管、独立备份及恢复由A10验收。

## A02及后续模块使用的接口

| 接口 | 当前职责 |
|---|---|
| `POST /api/v1/auth/login` | 账号密码验证，返回下一步；令牌仅写HttpOnly Cookie |
| `POST /api/v1/auth/mfa/enroll` | 持短期挑战获取首次绑定信息；已绑定账号不能重绑 |
| `POST /api/v1/auth/mfa/verify` | 验证动态码或一次性恢复码并签发完整会话 |
| `POST /api/v1/auth/logout` | 撤销当前会话和待验证挑战，清除Cookie |
| `GET /api/v1/me` | 当前账号及有效授权范围，不返回秘密字段 |
| `GET/POST/DELETE /api/v1/identity/users` | 管理员查询、创建、停用账号；DELETE是停用而非删除历史记录 |
| `GET/POST/DELETE /api/v1/identity/grants` | 管理员查询、授予和撤回对象动作授权 |
| `POST/DELETE /api/v1/identity/tokens` | 管理员签发和撤回单对象接入凭据，明文仅签发时返回 |
| 企业微信start/callback | 回调安全边界已实现并用替身验证；真实provider关闭，当前返回503 |

业务路由先调用`requireActor(request)`，再在读取/写入业务数据的事务内调用`assertAccess(client, actor, scope)`。范围列表使用`listAccessibleObjects`后限定查询，不能先加载全场数据再在页面隐藏。授权时间取服务端当前时间，`scope.at`仅用于业务时间，不能让客户端用旧日期延续权限。机器端调用独立的`assertIntegrationAccess`，不能伪造成Actor。

grant当前持有稳定对象UUID，A02建立对象表后补关联和对象存在性检查；本轮没有添加虚构地块或设备。人员授权表单随A02的对象选择一起接入，当前提供可测试的管理API。

角色动作上限如下。**表中允许不代表已授权对象；仍须对应grant。** 这是本轮采用的初始分工，修改时须同步测试和验收记录。

| 角色 | 动作上限 |
|---|---|
| 管理员 | 查看、配置、分享、导出；另有账号与授权管理 |
| 负责人、技术员 | 查看、记录、认领、关闭告警、审核、派单、分享、配置、导出、动作 |
| 工人 | 查看、记录、认领、关闭告警、动作 |
| 维护人员 | 查看、记录、认领、配置、导出、动作 |
| 外部专家 | 查看、审核、导出；无全场访问或派单权限 |

动作权限类型只是授权约束，**当前没有任何设备控制接口**；授予act不等于开放控制。后续仍须完成闸门等专项安全验收。

## 明确未验收的部分

- G03尚无企业应用配置、可信域名、测试成员和服务端兑换接口的实测契约。真实provider未启用；替身只证明state与浏览器绑定、一次性消费、未知/停用人员拒绝、已登记身份正确映射。真实浏览器跳转、企业微信客户端、令牌过期和网络故障仍须联调。
- 官方网页授权文档本次读取失败，未据未经核实的第三方字段编写真实适配器。接入时重新核对[构造网页授权链接](https://developer.work.weixin.qq.com/document/path/91022)与[获取访问用户身份](https://developer.work.weixin.qq.com/document/path/91023)。TOTP依赖按[otplib官方接口](https://github.com/yeojz/otplib)和本机13.5.0类型定义实现。
- 主设计的专家手机号加短信验证码登录未实施。当前专家角色用于本地权限验证，不能把密码账号当作已实现的专家短信入口。
- 业务对象、导出、附件下载、RAG、模型工具尚在后续工作项。A01通过的是授权公共入口与范围测试；这些真实业务入口须分别复用并回归，未提前宣告全链路权限验收。
- 密码重置、遗失验证器后的人工身份核验和安全重置尚无线上自助入口；不能通过删除MFA记录绕过核验。生产上线前补操作流程和演练，纳入A11交接。
- 全站公网HTTPS、代理层来源限流、日志保留清理策略、生产密钥保管和恢复演练仍须在部署阶段验证。本轮未证明生产安全评审、设备接入或RPO/RTO目标达成。
