## 实际窗口与指标

持续运行实测600.1秒，60个样本。先250条，再验证5000条可导出、5001条明确拒绝；列表既有200条上限继续公开标示，未冒称Q09分页已实现。

HTTP P50为25.03ms，P95为100.77ms；最大单轮操作418ms。内存/CPU采样、连接数及队列见机器记录。指标是指定硬件和合成数据窗口的测量，不外推全农场或长期稳定性。

真实故障包括仅终止自建worker后100任务四并发恢复、旧租约拒绝、仅终止自建PG连接的事务回滚、备份失败与重试；大文件断块/续传和原件恢复复用既有用例。双提交每轮仅产生一笔分录，队列最终归零。

## 发现并修复的实际缺陷

一次完整回归出现Node25在测试结束后的FileHandle垃圾回收错误。补充确定性断言后复现了“失败目标未消费输入，原件流仍未关闭”。在`src/modules/media/uploads.ts`共用流关闭处理，覆盖备份、组装及下载原件保存；保持原有校验、权限和错误语义。随后失败/成功两类文件流单测及相关集成通过，最终完整验收以修复提交重跑。

代码：`tools/check-stability.ts`、`tests/integration/runtime-faults.test.ts`、`tests/unit/media-stream-lifetime.test.ts`。十分钟是预先登记的工程窗口，不是生产RPO/RTO或长期现场验收。
