# 萤石签名消息接入验收

2026-10-02继续完成新版萤石签名WebHook软件入口。接收器、配置页面、独立消息/图片准备进程已实现；实际厂家推送、机型、图片和现场值守未验收，入口默认关闭。

## 已实现的链路

原始HTTP字节+t验签 → 脱敏后AES-GCM加密持久接收及camera.receive任务 → 返回原messageId → 独立worker按确认映射建立原告警/通知，并原子保存camera.image任务 → 独立准备原件下载 → 已有私有媒体下载/校验/备份。图片和模型都不占用厂家的接收确认时间。

- 接收限256KiB，拒绝非法UTF-8/JSON、压缩、缺签名、篡改及签名t超过5分钟偏差。签名算法按官方HMAC-SHA1，不重排JSON后验签。
- messageId防重复接收，同ID异内容冲突；alarmId另外防重复建警，厂家重试或新消息ID复述旧告警都不增加通知。接收确认表示原消息已可靠保存，不表示已派人或已建警。
- checksum在厂家报文中是设备解密密码，和password/token/secret等已识别字段去除后再归档。原字节SHA与脱敏摘要分列；密文、签名、图片URL、ISAPI负载不返回网页。
- 来源/设备/上级SN、同对象与厂家序列号/通道须核实。当前后台执行账号、read/record授权、身份版本、配置版本、来源契约和租约在处理时重查。
- ys.alarm使用设备发生时间；没有时区的时间按经核实的固定分钟偏移转换。推送/接收时间单列，不用它们代填发生时间。设备/通道矛盾、未映射、未知类型和ISAPI负载保留待契约，不猜字段或虚构风险结论。
- 自动图片默认关闭，只对crypt=0、URL加密标记明确为0且格式/CDN已核实的第一张主图安排下载；加密、无图、格式/域名条件不足各自显示。原告警与图片准备任务原子保存，进程重启后不会因提交间隙漏掉后补图片。

## 操作与部署

1. 配置管理登记本对象ezviz来源、接口和许可资料并核实；登记实物/通道与序列号，确认上级设备。建立拥有read/record的后台执行账号并授权。
2. “监控与航次→萤石签名消息连接”登记设备时钟、映射、原图格式及只读/原提醒交接依据；新连接默认停用。保存配置不在厂家开服务。
3. 私有部署环境使用`EZVIZ_WEBHOOK_ENABLED=0`；签名密钥变量`EZVIZ_WEBHOOK_SECRET`为与厂家控制台一致的16至64位字母/数字。本轮没有填写实际密钥或开启入口。公开回调使用HTTPS，路径为`/api/v1/ingress/ezviz/<连接ID>`。
4. `pnpm worker:cameras`独立消费消息和图片准备任务，`pnpm worker:media`继续下载及备份。网页显示可靠接收、已建警、待契约、阻断、失败和图片状态，能进入原告警。
5. 全局/连接停用、来源撤回或权限变化时不再接收或建警；已保存消息仍保留。条件不足的记录没有自动重放到新映射，需核对历史归属与具体契约后处理，不擅自把旧消息移到新对象。

## 真实联调条件

[官方使用指南](https://open.ys7.com/help/5129)明确，开通推送会停止原萤石APP提醒，关闭也不能自动恢复；开启厂家消息测试还会暂停投递原回调。实际开通前必须落实原值守提醒交接和厂家恢复安排。本轮没有操作这些设置，也没有改变布防、设备加密或控制。

HK-T4S8DM-GL/C03S08（4/4mm）究竟采用萤石协议还是海康ISAPI，须由供应商/实际固件确认。ISAPI还需确认订阅、云录制项目、原始JSON/XML负载、图片跳转获取与商业权益；当前加密保留，待契约不建警。旧设备告警列表已在官方菜单标注后续不维护，本轮不使用它冒充通用补数。

还需实测公网TLS与签名、重试是否重新生成t、厂家时钟、2秒压力、降级/丢弃及人工补数、真实白天/夜间/雨雾图片、20MiB限制及异地备份。签名时间窗口为当前软件选择，不宣称厂家所有重试均能通过。生产就绪与现场验收仍为false。

回退关闭全局开关并停止camera worker，使用上一版本构建，保留023接收记录与已入库原件，不逆迁移删数据。上一版本不会处理新camera任务，待恢复相应版本后重新核对状态。
