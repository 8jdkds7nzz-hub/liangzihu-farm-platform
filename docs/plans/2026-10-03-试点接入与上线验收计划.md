# 试点接入与上线验收计划

> 日期：2026-10-03。按用户已确认的顺序继续，由当前执行者逐项推进。本文完成的是执行准备；现场接入、外发通知、生产验收均未因此完成。

**目标：** 用一个明确范围的现场试点，验证真实采集、人员处置和业务对账，再决定哪些能力可以投入日常使用。

**实施方式：** 沿用现有平台和一至四期文档。先补真实资料，先只读接入；业务批次验证并行；厂家专有适配按各自条件开展。不新增一套系统，也不把未具备条件的模块算作已验收。

**技术基线：** 当前应用源版本 `cf032f1eeff67f1f5b86505bb4e71d8199f229c5`，Next.js 16.3.8、Node.js ≥ 22.15.0、pnpm 10.33.0。后续每次验收另登记当次提交、迁移、配置版本和环境；旧测试结果不自动适用于新代码。

## 一、范围与事实依据

建议首个试点范围为一个实际塘口或地块、一台已接入仁科云的设备、一组值班人员；另选一笔真实收发或加工业务。具体对象、设备、人员、批次尚未指定，先在[范围表](../试点/资料模板/01-试点范围与责任分工.md)填写核实，不预填型号、坐标、电话号码或农业阈值。

| 事项 | 当前资料支持的结论 | 本计划的处理 |
|---|---|---|
| 一至四期软件 | 软件能力及工程证据按各期交付核对；四期通用软件已交付 | 复用现有能力；每次适配变更追加回归记录 |
| 仁科 | 总体基线记录现有气象、土壤、水质设备已接入仁科云；逐台对应和真实契约仍缺 | 优先选一台核实，不能套用渔业报价型号 |
| 三诚闸门 | 基线为29套已安装；合同声明4G、485/Modbus、编码器与限位 | 仍需逐台核实、协议与共存路径；实际执行适配器尚未实现 |
| 监控与无人机 | 监控全场“80多路”与一批41台不是可相加的同一单位；机场3与Matrice 4TD为拟配线索 | 核对物理设备、通道、权益、实装；不推定已购或全场可用 |
| 新增能源 | 新增太阳能储能未采购，与闸门原配太阳能分开 | G16待采购及接口明确；不能阻塞已有设备的只读试点 |
| 生产恢复 | RPO 15分钟、RTO 2小时是总体设计目标；当前为同机工程恢复证据 | 在生产对应环境另验，不将本地恢复耗时填作生产结果 |

依据：[总体设计](../baseline/2026-10-01-智慧农业平台-design.md)、[四期软件交付](../releases/2026-10-03-四期软件交付核对.md)、[G01—G18总表](../试点/接入依赖与验收总表.md)。设备原件索引仍在外层工作区 `research-output/智慧农业软件框架设计/20260930_204932/供应商原始资料设备明细核对.md`，本次核读其3.2及设备差异说明；不复制合同、个人信息或报价原件到公开仓库。

## 二、推进顺序与验收层次

| 工作项 | 交付物 | 前置条件 | 当前状态 |
|---|---|---|---|
| P00 准备资料和验收机制 | 本计划、18项依赖总表、9份空白模板、准备记录 | 已确认推进顺序 | 本轮完成，验证结果见[准备记录](../acceptance/试点/准备进度与交付物.md) |
| P01 确定范围与核实台账 | 私有范围表、设备测点表、角色授权表 | 现场负责人提供真实对象及人员 | 待资料与负责人落实 |
| P02 仁科只读接入 | 核实契约、真实样本回放、接入对账 | P01，G02 | 待真实契约及样本 |
| P03 一笔真实业务 | 批次、凭证、分录、质量与去向对账 | P01，G13；循环等选做项另需G17 | 待真实批次，可与P02并行 |
| P04 告警与人员处置 | 专业规则、渠道实测、认领升级记录 | P02，G03—G05及适用G09 | 待规则与渠道条件 |
| P05 按条件扩展 | 厂家适配或专业业务的独立验收包 | 对应G07—G18条件 | 分项待资料，不整体勾选 |
| P06 部署与恢复 | 环境核对、独立恢复、目标差值记录 | G06，适用G12，选定试点范围 | 待实际部署资源与恢复人员 |
| P07 小范围试运行 | 每日记录、问题关闭、人员操作证据 | 本轮必需的P02/P03/P04及P06通过 | 未开始 |
| P08 范围签认与交接 | 已验功能清单、未验保留项、回退和维护交接 | P07证据完整 | 未开始 |

计划不预设开工日期。范围负责人落实P01后再填各项预计和实际日期；厂家回复、采购、检测等外部等待单列，不算软件已完成工时。首轮试运行沿用一期交接的**2至4周建议窗口**，由范围负责人结合生产周期确定；这是观测安排，不承诺到期自动通过。

验收分四层记录：资料已核实、工程验证通过、现场专项通过、限定范围试运行签认。只读试点可以先启动，但在告警渠道和恢复未通过前继续依靠既有值班与厂家系统，不宣称平台已接管值守。P08只能签认明确列入且通过的能力；未纳入范围不等于关闭对应G项，更不等于全平台生产验收。

## 三、责任与资料管理

| 责任角色 | 要完成的事 | 不能代签的事项 |
|---|---|---|
| 范围负责人 | 确定对象、人员、投入范围、时间窗口和最终使用边界 | 不用软件报告替代专业检测或厂家反馈 |
| 现场技术员 | 核实设备测点、采样和人工复测，确认专业规则与操作条件 | 不从未知型号补出协议，不代替独立质量/科研审核 |
| 值班与业务人员 | 日常认领、记录、实物盘点、收发和差异说明 | 不共用管理员账号规避权限 |
| 厂家接口联系人 | 提供适用版本、权益、字段和样本，确认系统共存及恢复路径 | 型号宣传或口头功能介绍不当实际契约 |
| 软件执行者 | 按真实契约适配、测试、部署记录与缺陷修复 | 不填造现场证据、农业阈值、签名和测试结果 |
| 部署与恢复负责人 | 私有配置、备份链、独立监测、恢复演练及运行交接 | 不以网页存活替代完整业务恢复 |
| 独立审核人员 | 检查工程部署、业务放行、科研或规则的对应证据 | 涉及软件要求独立审核时不能由提交者本人完成 |

上述是工作责任，不是新增平台角色。账户仍使用现有 `admin/owner/technician/worker/maintainer/expert` 及对象动作授权；`admin`不自动拥有业务录入和审核权。财务与管理报告另受财务角色范围限制。

空白模板在[资料入口](../试点/README.md)。本机填写副本放 `.local/试点接入/20261003_准备/`，真实附件放该目录的“原始资料”，凭据只进私有环境配置或密钥服务。模板用于人工收集和复核，不是数据库导入格式。收到资料后由软件执行者转换为现有表单或核实的接口契约；不宣称复制表格即可接入。

## 四、P01：确认范围、台账和授权

**输入：** 01范围表、02设备表、03人员规则表；G01原始照片、设备编号、厂家编号、对象和测点对应。

**输出：** 一份已签认的范围版本；一组可追溯的对象/设备/测点/来源/批次标识；两名以上适当分工的操作与审核人员（需要独立审核的业务不由同一人提交及审核）。人数是职责条件，不预填姓名。

- [ ] 范围负责人选定首个对象和首笔业务，区分已有、拟采购、报价线索及不纳入范围项。
- [ ] 技术员逐台对照铭牌、厂家平台与现场位置；同一物理设备下多个通道分别登记，记录绑定起止时间。
- [ ] 在现有“配置管理”登记经核实的对象、设备、测点和批次；核对后再赋予最小对象动作授权。
- [ ] 在私有环境演练角色读取、录入、独立审核、跨对象拒绝、撤权后旧页面/下载拒绝；记录实际账号代号。
- [ ] 记录值班替补、账号遗失/验证器遗失人工核验流程和培训；保留原用户登录设置，不擅自重置。

**通过条件：** 试点内逐行身份对应可回查；职责和替补明确；越权案例拒绝。缺一项时只开展资料整理，不写入未经核实的设备数据。

## 五、P02：只读真实采集

**代码入口：** [仁科采集](../../src/modules/telemetry/renke-pull.ts)、[持久化](../../src/modules/telemetry/ingest.ts)、[契约说明](../contracts/renke.md)。已有只读HTTP框架；多通道或状态表达不兼容时按实际契约扩展，不能假设完全免开发。

**验证入口：** [单元用例](../../tests/unit/renke-http.test.ts)、[数据库用例](../../tests/integration/renke-http.test.ts)。真实报文保持私有，提交到代码仓库的回归夹具须先脱敏且保留语义。

- [ ] 厂家资料明确版本、只读权限、端点/鉴权方式、分页、限流、令牌更新和历史窗口；02表填写原字段到标准字段的逐项依据。
- [ ] 收集正常值、零值、离线、无采样时间、同类多探头、重复/冲突、分页边界等真实样本。厂家无法提供的异常，用真实契约衍生受控测试，并标为“衍生”，不能算现场发生证据。
- [ ] 先在隔离环境回放；每条核对原值、标准值、单位、三类时间、对象及质量状态。失败批次不能前移游标；换塘前后按采样时间对应历史绑定。
- [ ] 如发现契约差异，先加可复现的定向测试，再做最小适配；每次修改运行相关用例、类型检查和正式构建。
- [ ] 只对已核来源启用只读取数，记录启用人、范围、时间和配置版本；短时间并行比对厂家页面/导出与平台记录。
- [ ] 在隔离或厂家认可的测试条件中验证断线、令牌失效、限流、重启续传和单探头中断；不为测试切断正在承担现场保障的设备。

**通过条件：** 给出完整比对分母、成功数、重复数、冲突数、缺失数及原因；所有差异可解释，未识别字段/时间/单位不进入有效测值。最大采集滞后、允许缺测率和比对时窗需在试验前由技术员依据采样能力登记；这些数值未确认则不能判定“实时达标”。

失败处理：关闭该新增来源取数，保留原报文、冲突、游标与平台历史；修复后从已确认游标重试，不能删除冲突或改原数据制造一致。

## 六、P03：一笔真实业务并行核验

**输入：** 04业务表，实际仓位、计量口径、来源单据、收发人与质量放行责任；依据G13，若选循环物料/费用/农机，再逐项满足G17。

**操作依据：** [3A操作卡](../help/三期3a操作卡.md)、[3B操作卡](../help/三期3b操作卡.md)、[4A操作卡](../help/四期4a操作卡.md)、[4B操作卡](../help/四期4b操作卡.md)。

- [ ] 仓管先核实期初实物、批次四种身份、仓位和单位；对历史补录单独标记业务发生时间与录入时间。
- [ ] 录入一次真实接收；再按实际发生的领用、加工、包装或交付继续记录，没有发生的步骤不能造单凑全流程。
- [ ] 对质量待检、报告适用范围、独立放行、去向和交接逐项核查；客户页先内部预览，只采用另经批准可公开的内容。
- [ ] 按同一单位和计量基准对账期初、入库、出库、转换、退回及期末；鲜干基不直接相减，称量差异需逐项解释。
- [ ] 用隔离副本演练重复提交、错误更正、部分交付、问题批追查和仍有未追回数量的案件；生产事实与演练记录分开。
- [ ] 如纳入费用，只登记凭证事实；费用、付款、受理、批准、到账日期分别核对，不在本次流程执行支付或政府申报。

**通过条件：** 原始凭证能找到平台记录，平台记录能回到实物与去向；差异有数量、单位、原因及复核人；更正保留旧版本。真实未发生的环节标为未验，不能用合成全流程补签。

## 七、P04：告警、通知和认领

**输入：** 03表；G03企业微信、G04语音和G05专业规则；需要生育阶段判断时另满足G09。

- [ ] 技术员确认适用对象、批次、单位、阈值、持续时间、新鲜度、滞回和恢复条件；样例规则不复制成正式值。
- [ ] 确认企业应用成员映射、可信域名、回执及验签；未知人员无法登录或访问对象。
- [ ] 登记允许联调的通知对象、电话、时段、模板、费用承担和终止人；由实施负责人核实授权证据后再安排测试，不能用空白模板作为外发授权。
- [ ] 在约定测试事件中记录“平台产生、服务受理、送达、电话接通、人员认领、处置关闭”各自状态与时间；不把HTTP成功当送达，不把接通当认领。
- [ ] 验证无人认领升级、替补值班、重复回执、迟到回执与回执丢失；保留事件和实际状态，不补造成功回执。

**通过条件：** 核定通知时限内可追到人员处置；失败能发现并进入既有值班渠道。测试事件不得通过伪造正常生产测值触发。渠道未验前，只读平台不替代现有报警与人工巡查。

## 八、P05：条件成熟后分别扩展

| 子项 | 必须先满足 | 后续动作与专门验收 |
|---|---|---|
| 监控、航次 | G07/G08实际型号、权益、样本和文件许可 | 事件—原件—航次身份对应、临时链接失效、大文件、私有权限；萤石推送切换对原APP提醒的影响和恢复方法先与厂家核实 |
| 地图、三维和终端 | G11-01—06、G12-01—03 | 使用05表；坐标与高程、独立检查点、排除区、连通性、容量和真实手机分别签认 |
| 日历、RAG与模型 | G09/G10及适用G14 | 使用06表；专业问题与独立标注集、引用质量、无依据拒答、延迟和费用；指标由专业审核预先确认 |
| 植保与多光谱 | G14 | 实际文件单位/时空基准、边界与障碍、原片校正和无效掩膜；工程计算成功不代替现场效果 |
| 闸门及其他执行器 | G15逐台设备、完整协议、共存路径和联合试验条件 | 先只读，再实现并测试实际驱动；请求、设备收到、电气动作、机械到位、实际效果分层核对；结果未知不盲目重发；现场停止和手动接管验证后仅对签认设备开放 |
| 新增能源 | G16实际采购、拓扑、寄存器和样本 | 编写具体只读适配；原值、倍率、功率方向、累计复位、间隔和电量差分核对；不自动控制负载 |
| 循环、农机、费用补贴 | G17来源/检测、五项书面答复、凭证与政策适用资料 | 使用04表；真实专有文件/HTTP适配，四类农机证据分别审核，实际量与计划量分开；登记不代表资格或付款批准 |
| 科研与综合指标 | G18，适用G09/G10/G13/G17 | 使用06表；真实独立重复与样本、旧结果回读、费用关联、专家撤权、指标分母和登记覆盖率 |

某项资料齐全即可进入对应开发，不等待所有厂家一起完成。每项必须先补“实际字段映射/适用版本—复现样本—代码改动—测试—现场验收”小计划，再实施；本计划不提前编造任何寄存器或厂家API。

## 九、P06：部署、恢复和回退

**输入：** 07表，生产对应云环境、私有存储与NAS/独立副本、独立凭据、监测通知及具名恢复人员。当前本机配置不等于云端部署模板，不能复制含凭据的文件进仓库。

- [ ] 在独立环境固定代码提交、迁移、依赖和构建；核实域名/HTTPS、Web与worker监管重启、日志、磁盘容量、对时、私有文件授权与外网暴露范围。
- [ ] 清点所启用的worker及依赖。检测Web存活及受保护的就绪状态；`/api/v1/health/live`返回200不能代替`/api/v1/health/ready`及具体业务检查。
- [ ] 核对备份链、可恢复时点、独立密钥取回、文件校验、备份失败通知及保留费用。每日NAS副本不能单独满足数据库15分钟目标。
- [ ] 在隔离恢复目标演练已选故障场景：云主机故障、误删、原云账号不可用；记录各场景是否纳入承诺以及实际覆盖程度，不对运行中的生产库执行删除式测试。
- [ ] 用事先登记的已提交业务记录验证故障前最后可恢复点；RPO＝故障时点减最新可恢复提交时点，另核对中间记录是否缺失。
- [ ] RTO从故障发生计时，到登录和权限、采集、告警与夜间电话升级、农事读写等设计要求业务核验完成为止；未验渠道必须标出，不能只报数据库恢复时间。
- [ ] 恢复后验证身份/撤权、私有附件、审核与库存关系、导入防重、旧报告、任务租约；恢复期间先隔离外发和控制，逐项核对待发任务后决定处理，避免补发旧告警或重复执行。
- [ ] 记录部署回退：旧版本是否兼容新增迁移须先验证；保留数据库和附件，不删除业务表“回滚”。回退前停止新增写入并保存状态，无法安全回退时暂停新增使用、恢复既有现场流程。

**通过条件：** 范围承诺对应的故障场景有实际恢复证据；RPO≤15分钟、RTO≤2小时分别有起止时间和差值；未达到就登记缺陷及补测，不改设计目标掩盖结果。私有文件按总体设计分级备份，单独记录实际丢失范围与恢复状态。

已有 `pnpm ops:phase4-restore` 只在 `agri_test` 自建随机schema演练，不能拿来充当生产灾备操作手册。具体云环境及恢复目标确定后，部署负责人必须补上对应命令、资源标识校验和停止点，再安排实际演练。
