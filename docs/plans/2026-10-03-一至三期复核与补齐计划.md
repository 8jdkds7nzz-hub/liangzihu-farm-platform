## 已发现的补齐项与设计

### R41 部分导入失败时保留输入

现状：共用 ActionForm 收到 `rows` 结果后无条件 `form.reset()`。植保导入一行成功、一行失败时，来源字段被清空；用户不能直接修正失败行重试。该组件起于二期界面整理，三期导入复用。

设计：收到行级失败时保留全部输入，逐行提示结果；整次提交键清空以允许修正后提交新请求，已成功行依其稳定外部编号由后台防重。完全成功才重置表单。网络结果未知继续保留原提交键。刷新列表失败不清掉已保存的输入。

修改：`src/components/platform/action-form.tsx`。测试：`tests/acceptance/phase4-regression-browser.test.ts`，使用真实植保导入端点和隔离测试库，不替换 HTTP 响应。

- [x] 复现：提交两行，仅一行合法；断言来源与行文本仍在，初始代码应失败。
- [x] 修改重置条件；部分成功后的提示必须包含“未导入”，不能显示整批已完成。
- [x] 将失败行改正后重试；数据库只应存在两条实际作业，成功行不重复。

### R42 一、二期表单的账号切换保护

现状：ActionForm 只为三期 URL 添加原账号标识。此前打开的一、二期管理表单在浏览器切换到另一个同样有权限的账号后，可能以新账号提交原草稿。

设计：共用表单发送 `X-Expected-Actor-Id`，取页面首次打开时的 ActorSnapshot；共用 `requireActor(request)` 解析当前会话后验证该请求头。失配返回 403 ACCOUNT_CHANGED，保留输入；不携带该头的既有 API 调用继续按原鉴权约束运行，避免破坏外部客户端。三期已有 body 检查保留。该标识用于防止误提交，不能替代会话和对象权限。

修改：`src/components/platform/action-form.tsx`、`src/modules/identity/session.ts`。测试：同一文件中用两个都具备 configure 的技术员打开“登记来源”表单，切换 cookie 后点击保存，验证无新增来源；另验证三期原测试继续通过。

- [x] 先跑浏览器复现：旧代码会新增来源，预期拒绝断言失败。
- [x] 将检查放到实际会话解析之后，不能信任请求头所声明的身份。
- [x] 验证无头正常调用、同账号提交、账号切换和撤权拒绝。
