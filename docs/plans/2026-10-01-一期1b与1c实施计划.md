# 一期1b与1c实施计划

> 按用户已授权的自主执行方式，在本会话逐项实施；不再等待例行选择。当前宿主没有superpowers执行工具，采用同等的逐项实现、测试及证据记录，不声称调用不存在的技能。

**Goal:** 完成现场记录与影像、分析与智能助手的可运行本地实现。

**Architecture:** 复用A11接口，新增独立领域模块；业务事务、文件I/O和推理进程保持明确边界。

**Tech Stack:** Next.js16.3.8、TypeScript5.9、PostgreSQL18/PostGIS3.6、pgvector、私有S3或本地目录、IndexedDB、Transformers.js。

## Global Constraints

- 采用已批准的总体设计和本目录设计，不开放设备控制、自动派单或真实外发。
- 所有读写入口当前授权校验；原件、提交与更正链保留，资料撤回失效。
- 新增迁移从011开始，应用过的000—010不得修改。
- 合成样本仅agri_test与临时文件目录；G01—G10实测缺口单独登记。

失败测试示例采用既有`withDb`、`transaction`和fixture，无全局锁或访问开发库：

```ts
await assert.rejects(() => transaction(c => submitRecord(c, worker, {
  objectId, submissionId, attachmentIds: [missingAssetId], objectVersion: 1,
  kind: 'inspection', occurredAt: '2026-10-01T01:00:00Z', content: { observation: '合成' }
}), pool), { code: 'ATTACHMENTS_INCOMPLETE' });
```

文件上传写入私有存储后，数据库状态最后提交；I/O成功而事务失败时保留不可公开孤立文件，重试按稳定键和哈希核对，不能声称跨存储原子事务。数据库失败不删除历史文件。恢复先恢复到独立schema及媒体目录，逐表和逐文件校验后实际读取；不得直接覆盖生产数据。

## 回退

部署回退到A11构建时保留新增表与原件，不降级删除迁移；停新增媒体/推理进程即可，A链路不依赖B/C表。对象存储与推理外发均关闭后仍可读取已有权限内资料。正式生产回退须先用新增表和数据实测旧构建兼容。
