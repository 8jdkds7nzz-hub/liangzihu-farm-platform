**价值与已有能力：** 现有测试内容丰富，但命令分散，重跑部分浏览器测试会覆盖历史截图。先让今后每次修改都有明确、可复现的检查范围。

**落点：** 修改`package.json`、`tests/support/`及存在固定输出路径的测试/评测/恢复脚本；新增拟定的`tools/check-project.mjs`与`tests/support/artifacts.ts`。这些新路径尚未实现，不是当前可运行命令。

- [ ] 统一产物目录为`.local/验证记录/<run-id>/`，每次运行登记提交、套件、环境、失败/跳过、耗时及产物哈希；不把重复测试计为新增用例。
- [ ] 改用公共产物路径函数，检查所有固定截图/JSON写入；旧`docs/acceptance/`只保留原件，需要交付时显式复制脱敏结果到新目录。
- [ ] 检查失败或前置缺失时返回非零并输出具体原因；模型未下载时明确“未执行”，不计通过；禁止检查命令自行操作开发库。

**交付及验收：** 一份命令清单、统一入口和独立运行清单。连续执行两轮得到两个结果目录，历史验收哈希不变；植入一个故意失败的临时用例能令整轮失败；清理该临时用例后正常通过。使用临时分支/夹具，不提交故意失败代码。

- [ ] 将试点02表中已核字段逐项映射到现有契约；多探头、历史绑定或厂家状态不兼容时另列具体适配，不自动猜测。

**交付及验收：** 错误对象、重复行、缺引用和超过50行有明确行号；预览零写入；预览后撤权会阻止提交；重复提交不产生重复设备。真实G01/G02仍需现场核实。先验证原有防重行为，再针对复现差异修复，不能预先宣称已发现重复设备漏洞。

## 十一、Q09：历史查询与稳定分页

**价值：** 累积记录超过首屏范围后，业务人员应能查到旧记录，而不是只能在最近200条里筛选。金额或指标的全范围汇总仍保留现有数据库口径。

**落点：** `src/components/platform/data-list.tsx`、库存/费用/科研的`queries.ts`及对应API/页面；先做三条高价值路径，再按相同约束扩到其他确有需求的列表。

- [ ] 设计服务端对象、日期、编号/名称、状态筛选及下一页接口；所有记录先按当前权限筛选，再做分页，禁止先截200条再过滤权限。
- [ ] 每类列表使用确定排序及唯一键，游标绑定筛选/对象范围；记录首轮查询范围边界，避免并发插入造成遍历漏项或重复。更正版本与当前版本分别标明。
- [ ] 前端显示当前筛选条件、已加载数量、是否还有下一页；切对象或换筛选清空旧页，跨账号不保留另一人的数据。
- [ ] 引用选择器也能找到历史记录，不能列表能翻页但录入表单只能选择最近200条。详情、导出和统计各自保留权限与已定上限。

**交付及验收：** 分别构造至少250条库存、费用和科研相关合成记录，能按编号找到第201条以后的记录；同时间多条、翻页中新增、撤权、同名跨对象均有断言；遍历固定范围不漏不重。列表分页不改变汇总总额，也不能借机取消导出的大小限制。

## 十二、Q10：手机操作与可访问性

**落点：** 共用表单/列表/引用控件、现场记录与告警页面、`tests/acceptance/`相关浏览器用例。

- [ ] 优先验证六条路径：登录、认领告警、农事拍照/离线草稿、设备配置、批次收发、审核与更正。
- [ ] 检查字段标签、必填/单位提示、键盘与焦点、错误跳转、长编号/大字、手机弹出键盘与单手操作；从可复现问题修复，保留二期既有布局。
- [ ] 验证请求超时、丢响应、重试、切对象/账号和网络恢复后输入状态，复用已有防重与草稿机制，不另造同步系统。
- [ ] 区分浏览器模拟视口、真实桌面浏览器与真手机/企业微信结果。真实终端未取得时留下G12，不填造设备型号。

**交付及验收：** 六条路径有工程操作记录和修复前后证据；键盘可完成核心表单、错误可定位、失败不丢输入。随后由实际人员记录完成率、耗时及误操作，才能关闭现场易用性项。

## 十三、Q11：容量、长时间运行与故障恢复

**落点：** `tests/support/`合成夹具、任务/媒体/业务查询的现有用例、`ops/`，必要改动只针对测到的瓶颈。

- [x] 定义可重复的数据档位，覆盖超过200条列表、接近现有5000条导出边界、后台任务积压、大文件和并发提交；具体规模不冒充真实全场规模。
- [x] 记录硬件、数据量、并发、查询/接口耗时、内存、CPU、文件空间和任务等待；先建立基线，再决定是否加索引或优化逐条查询。
- [x] 在隔离环境测试worker被终止、网络替身超时、数据库短暂不可用、附件下载中断、备份失败；检查租约、防重、游标和失败提示。
- [x] 做一个事先约定窗口的持续运行试验，观察队列是否回落、内存和连接是否持续增长；修复后同档位复测。

**交付及验收：** 可重跑的负载场景与容量报告，明确测得上限和未测范围。无重复分录/任务副作用、无静默漏数据；性能目标先登记再测，不事后调整目标使结果通过。生产硬件/流量及15分钟RPO、2小时RTO仍归G06/G12。


实际执行见[本轮工程交付](../acceptance/产品化/工程完善交付核对.md)，勾选仅指本轮工程范围。

## 十四、Q12：权限与业务一致性组合回归

## 十五、Q13：AI检索与专业评测准备
