# 工程验证自动化与发布可靠性实施计划

> 按用户已批准顺序自主执行，沿用writing-plans；由当前执行者完成，不另派代理。设计见[工程验证设计](../specs/2026-10-03-工程验证自动化与发布可靠性设计.md)。

**目标：** 完成检查保护、可复现测试环境、远端回归、诊断/覆盖、发布和稳定性工程闭环。

**架构：** 复用Q01执行器、现有数据库和测试辅助；新增小型工具模块，业务代码不为工程工具重构。Next相关验证读取已安装版本的测试/构建指南。

## S1 检查保护与环境

- 文件：`tools/verification.ts`、新增`tools/quality-state.ts`、`tools/check-environment.ts`、`tools/setup-test-environment.mjs`、`tests/support/postgres.ts`，四组恢复脚本改为共用已核测试容器调用。
- [x] 添加并发锁、原子报告、运行中进度、源码变化、中断、无用例等反例，再实现相应保护。
- [x] 创建独立测试环境及所有权标记，补错误配置、错误库/角色/标记的拒绝检查；不修改原开发数据库。
- [x] 增加core和固定套件清单，保留delivery全量；失败重跑保持原结果。
- [x] 运行定向单元与测试环境自检；每项有实际退出码。

## S2 自动回归与干净安装

- 文件：`.github/workflows/verify.yml`、`tools/check-project.ts`、`package.json`、测试环境脚本和冷安装核对记录。
- [x] 全新副本冻结安装、生成独立配置/库、正式构建和核心浏览器；不复制开发凭据。
- [x] 配置PR/push core及显式完整delivery；动作固定版本/权限，产物只上传公开摘要。
- [x] 在授权仓库分支推送已通过本地定向验证的实现，实际执行LinuxCI；记录提交、URL、失败修复和最终结论。
- [x] GitHub账户/配额阻塞时保留准确外部阻塞原因并继续独立工作；本轮已通过既有协作者授权解除远端阻塞，Linux以全新GitHub执行器实测为准，不伪造远端成功。

## S3 诊断、需求对照与公开报告

- 文件：新增`tools/check-coverage.ts`、`tools/check-report.ts`、相应单元测试及需求映射配置；复用既有验收文档。
- [x] 提取私有失败用例、复现命令、首次/重跑结果，保留不稳定线索。
- [x] 校验1A—4C代码/测试/证据链接，分别报告结构覆盖、运行覆盖和历史变更。
- [x] 用敏感内容探针测试公开摘要白名单；摘要不能复制任意日志、凭据、转储或业务原件。
- [x] 把coverage步骤纳入core/delivery，真实缺口逐项修复或按现有G门槛标明，不按空壳文件充数。

## S4 发布、回退与稳定性

- 文件：新增`tools/release-manifest.ts`、`tests/acceptance/release-upgrade.test.ts`、`tools/check-stability.ts`及故障用例；必要时扩展`tests/support/app.ts`的独立旧版本目录参数。
- [x] 发布清单拒绝过期验收、源码/锁文件/迁移变化与不完整结果。
- [x] 旧版独立构建与非空数据升级，故意失败迁移回滚，成功升级后旧代码兼容回读；原账号和业务内容保持。
- [x] 250/5001记录、100任务、并发、连接中断和worker退出的隔离测试。
- [x] 完成事先约定的10分钟持续测量及至少30个采样点；保留硬件/数据量/时延和未知生产范围。

## 收口

- [x] 全量delivery、恢复、发布演练、稳定性与远端CI分别记录；重跑不累计独立测试总数。
- [x] 新增使用说明、分项设计代码测试对照和脱敏交付记录；保留旧证据，更新当前导航。
- [x] 合并本轮明确文件，保留主目录AGENTS/技能入口/生成资源及其他并发改动；现有服务不自动升级或停机。

实际分项、修复、失败保留和范围边界见[工程交付核对](../acceptance/产品化/工程完善交付核对.md)。
