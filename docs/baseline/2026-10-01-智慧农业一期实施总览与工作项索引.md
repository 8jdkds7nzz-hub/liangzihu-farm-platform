## 一 本期交付什么

一期让值班人员及时看到异常并留下处置记录，让工人能在现场可靠记农事，让技术员在可追溯数据基础上审阅每日建议。用真实业务流程组织开发，模块编号继续沿用M1—M22。

| 阶段 | 用户可完成的事 | 文档及完成边界 |
|---|---|---|
| 1a | 管理员登记对象与设备；值班人员接收、认领、核查告警；技术员核对读数；运维能发现故障并恢复 | [基础平台与监测告警详细计划](2026-10-01-智慧农业一期1a基础平台与监测告警实施计划.md)。范围包括后台基础设施及接口契约 |
| 1b | 工人记农事、处理任务和离线暂存；技术员查看地图、监控与航次成果、编制农事日历 | [现场作业与影像管理计划提纲](2026-10-01-智慧农业一期1b现场作业与影像管理实施计划提纲.md)。1a契约稳定后展开逐文件编码步骤 |
| 1c | 技术员查看指标和依据、审阅简报、使用权限内问答；模型后台复核图片 | [分析与智能助手计划提纲](2026-10-01-智慧农业一期1c分析与智能助手实施计划提纲.md)。数据与资料样本到位后展开编码步骤 |

三阶段分别验收，一期末再做跨阶段联调。1a能交付独立的监测告警能力；只通过样例回放的设备接口仍标记为未完成真实接入。1b、1c目前是有工作项和验收标准的提纲，不宣称已经达到逐步编码计划的细度。

## 二 借鉴Plane怎样组织工作

Plane将任务作为Work Items，用Modules组织功能，用Cycles组织有起止时间的执行窗口，用Views筛选工作；这些概念见[工作项属性](https://docs.plane.so/work-items/work-item-properties)、[Cycles](https://docs.plane.so/introduction/tutorials/plan-and-create-cycles)。本项目采用以下映射，不依赖某个商业版本才有的功能：

| 组织层 | 本项目用法 |
|---|---|
| Project | 一个“智慧农业平台研发”项目，对应一个独立私有代码仓库 |
| Modules | 沿用M1—M22；一张工作项可以涉及多个模块 |
| 阶段标签 | 1a、1b、1c是交付阶段，不直接当作已经有工期承诺的Cycle |
| Cycle | 执行时按团队实际可用时间排一周左右的窗口；仅放入输入已齐全的工作，不提前虚构日期 |
| Work Items | A00—A11、B01—B07、C01—C07，每项有用户结果、依赖、交付和验收证据 |
| Views | 本周可做、外部依赖、待验收、缺陷回归、按阶段查看 |
| Pages | 总设计与本组计划；后续每阶段的发布说明、操作卡及验收记录 |

建议工作项状态：未准备 → 可执行 → 进行中 → 待验收 → 已完成；取消单独记录。外部阻塞另记原因、责任角色、所缺证据及复查点。没有实测证据的工作不能因代码已合并而标为已完成。

每张工作项的固定字段：编号、关联M模块、用户及场景、需要解决的问题、范围、前置依赖、负责人角色、实施文件、验收步骤、证据位置、失败及回退方式。负责人角色用于分工，执行前绑定实际人员，不虚构已安排的姓名。

## 三 产品目标与完成证据

| 用户 | 首要结果 | 一期观察指标 |
|---|---|---|
| 当班人员 | 找到需要核查的对象并明确认领 | 告警发起到认领时长、未接管数量、核查结果完整性 |
| 技术员 | 判断依据清楚、能发现资料不足 | 有效数据覆盖、指标及引用可追溯、简报修改与驳回原因 |
| 一线工人 | 少填字段，记录和照片不丢、不重复 | 现场填报完成情况、失败重试、离线草稿恢复及重复记录数量 |
| 老板 | 看到重点和未解决事项 | 待拍板事项来源、未闭环风险及交接责任 |
| 运维人员 | 故障能被发现、数据能恢复 | 实时链路健康、任务积压、备份落后、演练实测RPO与RTO |

固定目标继续使用原设计：夜间严重告警3分钟无人认领触发电话；数据库最大可接受数据损失15分钟；核心业务恢复2小时。30天恢复窗口和全部联系人未响应后的5分钟合并提醒为推荐初值，需按原设计复核。其他指标不擅自填入所谓行业达标值。

## 七 文稿与执行证据的管理

当前仓库保存设计和计划；后续代码在独立私有平台仓库。平台仓库内用`docs/acceptance/1a/`、`1b/`、`1c/`保存执行证据，文件名使用工作项编号。证据至少记录版本、环境、样本、步骤、实际结果及操作者；不保存明文密钥或完整个人敏感信息。

每阶段验收分为程序测试、真实接口联调、现场使用、运维恢复四类。缺少其中相关证据时只能标记部分通过，不用截图或成功日志代替完整流程。发布说明写清新增能力、影响角色、数据迁移、已知限制和回退方式。

本文和三份计划是产品与研发工作组织文件，不代表已在Plane创建项目、绑定人员或安排实际日期。
