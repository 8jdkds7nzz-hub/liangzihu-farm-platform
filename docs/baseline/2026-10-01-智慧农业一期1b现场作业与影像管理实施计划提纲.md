# 智慧农业一期1b现场作业与影像管理实施计划提纲

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> 执行方式以用户授权与宿主能力为准。本文件是提纲版，有业务交付、依赖和验收，尚未展开为逐文件编码指令；不能把本提纲当作已完成开发。

**Goal:** 工人在手机可靠记农事与处理任务，技术员能把记录、地图、监控及无人机成果对应到同一对象。

**Architecture:** 复用[1a计划](2026-10-01-智慧农业一期1a基础平台与监测告警实施计划.md)的身份、对象、事件、持久任务和权限接口。媒体原件保存于私有对象存储，业务库保存标识、版本、关联与状态；离线草稿先保存在设备，联网后按同一请求标识同步。

**Tech Stack:** 延续1a的Next.js、TypeScript和PostgreSQL/PostGIS；地图、对象存储客户端及离线存储实现按真实机型和样本验证后锁定依赖，不为使用Plane引入另一套业务技术栈。

## Global Constraints

- 一个系统、一套账号、一个数据库；全部路径相对于独立平台仓库。
- 原值永不覆盖；更正新增记录并保留理由。
- “已存本机”“待同步”“已同步服务器”分别显示。
- 恢复网络并打开应用后上传；同步时重新校验身份、权限和版本。
- 不自动派单、不自动对外发送，照片尚未完整上传时不能把整次提交显示为已同步。
- 外部专家只访问明确授权的事项、数据时段和附件；权限到期或撤回后后续访问失效。
- 主设计数据库15分钟恢复点、核心业务2小时恢复目标继续有效，本阶段增加农事与附件实测范围。
- 一期只做二维；三维二期、多光谱三期；闸门按独立插入式验收处理。

## 一 用户场景与交付指标

主场景：工人到一个塘口或地块，选择或扫码识别对象，记录发生时间、工作内容和照片；信号差时存草稿，联网后同步；技术员在同一对象详情查看记录、照片和相关测值，核查后留意见。

其他场景：人员领取正式任务并反馈；技术员录入审核后的农事日历；值班人员在告警中看到监控图片；查看某航次原片和成果及其覆盖范围。观察填报完成率、失败与重试、重复记录、附件完整性和任务交接情况，实际目标在测试前登记。

- 有受支持手机的测试清单及可用的私有对象存储。缺某厂商资料可开发对应通用流程，真实接入保持未验收。

## 三 文件与接口归属

下列为规划职责，详细编码计划须根据1a实际文件核对后使用。

| 责任 | 推荐文件范围 | 消费或产出 |
|---|---|---|
| 地图和空间对象 | `src/modules/map/`、`src/app/(platform)/map/` | 消费objects/object_versions，输出二维图层和对象选择 |
| 农事与同步 | `src/modules/farm-records/`、`src/modules/mobile-sync/` | 消费Actor/Scope，输出正式记录、客户端提交回执和更正链 |
| 媒体资产 | `src/modules/media/`、`workers/media.ts` | 文件标识、版本、校验、对象关系及备份状态 |
| 监控适配 | `src/adapters/ezviz/` | 设备与通道、外部事件ID、图片引用、授权播放入口 |
| 航次适配 | `src/adapters/dji/`、`src/modules/flights/` | 航次、媒体清单、成果版本和缺失文件 |
| 日历 任务与巡查 | `src/modules/calendars/`、`src/modules/tasks/`、`src/modules/inspections/` | 审核版日历、批次计划、人工派单与反馈 |

供1c消费的最小业务结果采用以下结构，在完整计划中映射到SQL和API；不得把模型建议写成已执行农事：

```ts
export interface FarmRecord {
  id: string; objectId: string; batchId: string | null; kind: string;
  occurredAt: string; recordedAt: string; authorId: string;
  status: 'draft' | 'submitted' | 'reviewed';
  version: number; supersedesId: string | null; attachmentIds: string[];
}
export interface MediaAsset {
  id: string; objectId: string; version: string; checksum: string;
  capturedAt: string | null; sourceId: string; storageKey: string;
  ingestState: 'pending' | 'complete' | 'failed';
  backupState: 'pending' | 'verified' | 'failed';
}
export interface CalendarVersion {
  id: string; version: number; species: string; variety: string | null;
  sourceRef: string; approvedBy: string; effectiveFrom: string;
  retiredAt: string | null;
}
```

API的正式记录返回值不包含公开存储地址。文件查看与下载经过当前权限检查；storageKey只在服务器内部使用。

## 四 按业务结果组织工作项

### B01 在地图上找到正确对象

**用户结果：** 地块、塘口、设备及成果图层能对应，未核实资料可见但不冒充确定边界。

**依赖与范围：** A02、G01；二维图层、边界版本、空间查询和对象选择，不提前建设三维。

- [ ] 核对坐标系、来源、边界确认人及版本；准备至少两个相邻但不连通对象的样例。
- [ ] 用既有对象ID显示地图和设备；地图点击后进入同一对象详情，不能新建一套地图对象身份。
- [ ] 显示未核实映射及缺失坐标，不凭邻近推定设备归属或水力连通。
- [ ] 对边界修改前后记录做回查，确认历史对象关系未重写。

**验收证据：** 来源边界与界面对应、坐标核对、权限内空间查询及历史版本记录。输出`B01.md`。

### B02 一次农事提交及附件完整保存

**用户结果：** 工人完成最少必要字段，技术员看到同一记录和完整照片。

**依赖与范围：** A01/A02、私有存储；农事表单、上传、表格补录、更正及分级备份。

- [ ] 定义每类农事的必填字段及单位，发生时间与录入时间分开；不让系统填写未知用量为0。
- [ ] 同次提交使用稳定请求标识；表单和全部必需附件成功后才确认已同步服务器。
- [ ] 表格补录逐行显示错误并保持原行号；修正后重试不重复导入已成功行。
- [ ] 关键照片上传后创建备份任务，复制且校验成功才标记verified；备份失败不撤销已经成立的业务记录，但状态和缺口可见。
- [ ] 对同一附件验证网页、后台读取、导出和恢复；缺文件不返回假成功。

**验收证据：** 重复请求、响应丢失、部分附件失败、原值更正链、恢复后引用与校验值。输出`B02.md`。

### B03 信号差时继续填写 恢复后安全同步

**用户结果：** 关闭再打开仍保留本机草稿，联网后一次性形成正确正式记录。

**依赖与范围：** B02、实际手机清单；首次在线登录及必要页面准备后才承诺离线能力。

- [ ] 区分已存本机、待同步和已同步服务器，草稿按账号隔离。
- [ ] 表单与照片本地持久化失败必须提示；空间不足时不显示保存成功。
- [ ] 联网并打开应用后查询或重试原提交；提交后确认丢失也不能形成重复农事。
- [ ] 同步时重新检查授权与记录版本；冲突或失去权限时保留草稿待处理，不直接覆盖服务器。
- [ ] 企业微信与备用浏览器分别做飞行模式、关闭重开、照片上传中断及切换账号测试，登记版本及支持范围。

**验收证据：** 真机录像或操作记录、提交ID、最终数据库记录、各状态截图。输出`B03.md`；本机草稿不表示服务器任务或告警已经改变。

### B04 监控告警先到人 图片后补

**用户结果：** 值班人员及时知道哪个对象有事件，随后查看图片或权限内回放。

**依赖与范围：** G07、A05/A07、B02；按真实台数与通道授权，不把80多路等同于80台。

- [ ] 保存外部事件ID、设备和通道、发生及接收时间，重复推送关联原事件。
- [ ] 事件持久保存后先通知，图片独立获取；过期链接或取图失败可重试，不生成第二条告警。
- [ ] 预置位抓拍、休眠唤醒、回放和临时播放地址分别实测，记录流量、功耗影响与权限限制。
- [ ] 准备白天、夜间及未触发告警时段的独立样本，供C05评估；本阶段由人工判断。

**验收证据：** 厂家消息、平台事件、首次通知和后补图片时间；重复回调、离线和无权访问结果。输出`B04.md`。

### B05 航次成果完整入库并备份

**用户结果：** 技术员知道某次飞行取得哪些原片与成果，哪些仍缺失，可定位到对象。

**依赖与范围：** G08、B01/B02；机场和司空按实际版本与权益接入，多光谱只留结构和独立导入路径。

- [ ] 将航次、文件清单、成果版本、坐标基准及处理来源分开保存；不得只存一个临时下载URL。
- [ ] 失败后按稳定文件标识续取与核对，清单未完整时显示缺失，不宣告航次全部接入。
- [ ] 原片、正射及其他成果保留加工关系；拍摄条件不足的跨期比较标明限制。
- [ ] 航次或成果批次完整后安排备份；逐文件校验，再标记备份完成。
- [ ] 用一次真实航次验证从厂家到对象详情、再到恢复副本的全链路。

**验收证据：** 机型与司空接口版本、原始清单、下载及缺失记录、校验值和恢复结果。输出`B05.md`。

### B06 日历 人工派单与巡查交接

**用户结果：** 技术员维护审核后的农事日历，人工确认任务，工人领取反馈，交班可见未完成事项。

**依赖与范围：** A01/A02、B02、G09；包括人工灌排台账，不开放未经联合验收的闸门控制。

- [ ] 日历按物种、品种、生产阶段和依据分版本；草稿不用于C01时间窗判断，审核或撤回留痕。
- [ ] 任务草稿与正式任务分开，派单须有dispatch权限；简报审阅或建议采纳不自动派单。
- [ ] 巡查回填区分观测、判断、动作，未反馈不显示已到场；灌排操作记录申请、确认、执行、结果与未执行原因。
- [ ] 处理领取竞争、任务变更及交班；同一现场问题关联告警、任务和反馈，不重复建立互不关联的记录。

**验收证据：** 一份已审核日历、正式派单与反馈、被拒绝的越权派单、灌排记录及交班清单。输出`B06.md`。

### B07 现场使用与恢复验收

- [ ] 按总览分配完成R04、R05、R21—R24及本阶段相关验收；权限、恢复、真实报文和培训重复验证新增部分。
- [ ] 由工人和技术员各完成一条真实操作链，记录失败与改进，不用演示者代替实际使用者。
- [ ] 恢复包含农事及附件的数据，核对对象关系与访问授权；记录新增业务下的RPO/RTO及未恢复文件。
- [ ] 发布B阶段操作卡和说明，保留未验证设备、机型、浏览器及接口限制。
- [ ] 固定供1c使用的数据和事件契约版本，再展开1c编码计划。

输出`docs/acceptance/1b/B07.md`及阶段发布说明；全部代码任务在展开后的详细计划中指定测试文件、命令和迁移步骤。
