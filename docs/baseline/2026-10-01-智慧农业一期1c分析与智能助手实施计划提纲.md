# 智慧农业一期1c分析与智能助手实施计划提纲

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> 执行方式以用户授权与宿主能力为准。本文件为提纲版；工作项及验收已经拆分，逐文件编码步骤在1b数据契约和评测样本到位后展开。

**Goal:** 技术员每天得到有依据、能审阅的关注事项，老板与工人收到经过确认的适用内容；权限内问答与图片复核可评测、可降级。

**Architecture:** 程序计算指标、判断质量与权限；RAG提供经审核的相关资料；模型解释并生成草稿，正式任务和外发继续由有权人员确认。图片复核、简报与问答任务独立于实时告警运行。

**Tech Stack:** 沿用1a/1b的TypeScript、PostgreSQL、对象存储与持久任务；pgvector与关键词检索、独立模型及向量适配器。现有网站模型调用代码可参考，不直接照搬模型参数、超时或全库检索逻辑。

## Global Constraints

- 指标由程序计算，大模型负责解释；阈值和处方来自专业人员。
- Kimi为主、DeepSeek备用；备用切换遵守事先授权，不因失败擅自扩大数据发送范围。
- 未审核、已撤回或无权访问的资料不能进入模型上下文。
- 缺测不计正常，不自动推定异常持续；数据不足显示“暂不能判断”。
- 不自动派单、不自动对外发送；人员图片不发给文字大模型，输入去除人名、手机号与精确位置。
- 模型故障不阻塞采集及告警；未完成图片复核不能写成无异常。
- 试运行2至4周，先给技术员看并评价；正式推送须完成当前设计的审核流程。
- 本阶段不实现作物识别、多光谱分析或自动设备控制。

## 一 产品场景与成功判断

主场景：程序在清晨形成带数据质量的关注事项，技术员逐条查看事实、依据与限制，采纳、修改或驳回；有派单权限的人确认任务后交给工人，老板看到重点和未解决事项。

问答场景：用户在自己权限内查询数据和资料，能打开支持答案的来源；没有依据、条件不足和服务不可用分别说明。图片场景：值班人员先收到摄像头告警，模型在后台追加复核结果，人工判定和原告警保持独立。

完成标准同时覆盖正确性、可追溯、权限、稳定性、耗时和费用。用户点赞或一次演示成功不能单独替代固定评测。

## 二 输入与模块职责

输入来自A11、B07：对象、批次、测值、缺测、告警、农事、任务、媒体及日历的稳定ID和版本。G09提供专业定义、资料及参考问题，G10提供模型、向量、天气和图像项目的实际能力及许可。

| 文件范围 | 职责 | 主要产出 |
|---|---|---|
| `src/modules/analysis/` | 指标定义、质量与可比性、补传重算 | 带定义版本和证据的指标 |
| `src/modules/weather/` | 实况、预报、预警和历史基线 | 来源、发布时间和有效时段 |
| `src/modules/knowledge/` | 审核版本、切分、检索、撤回 | 可追溯且权限内的段落证据 |
| `src/modules/assistant/` | 受限工具、模型适配、费用、验证 | 结构化草稿和明确的失败状态 |
| `src/modules/briefings/` | 审阅、角色版本、周月报 | 审批链及发布记录 |
| `src/modules/image-review/` | 异步图片分析与人工对照 | 模型输出、版本、置信度及状态 |
| `tests/evaluations/` | 固定评测与版本比较 | 逐题结果、重复运行、质量耗时费用对照 |

## 三 供各模块共用的结果结构

```ts
export interface MetricResult {
  id: string; objectId: string; definitionId: string; definitionVersion: number;
  windowStart: string; windowEnd: string; calculatedAt: string;
  value: number | null; unit: string;
  status: 'usable' | 'insufficient' | 'incomparable';
  coverage: number | null; limitations: string[]; evidenceIds: string[];
}
export interface KnowledgeEvidence {
  documentId: string; version: string; chunkId: string;
  text: string; scopeObjectIds: string[]; sourceUrl: string | null;
}
export interface ProposedAction {
  objectId: string; factRefs: string[]; sourceRefs: string[];
  assessment: string; suggestion: string; limitations: string[];
  status: 'draft' | 'adopted' | 'modified' | 'rejected'; reviewerId: string | null;
}
```

指标为空与数值0不同；模型不能把insufficient改成usable。用户输入、资料正文和模型输出都不能自行授予工具权限。

## 四 工作项与验收提纲

### C01 指标 天气与农事时间窗

**依赖：** A03/A04、B02/B06、G09/G10。

- [ ] 把第8.4节的公式、单位、时区、窗口、完整性和适用条件变成审核版定义；保留版本和测试样例。
- [ ] 用固定数据计算均值、极值、持续时长和完整率；缺测区间保持未知，补传只重算受影响历史版本。
- [ ] 区分现场实况、外部预报及历史基线；按定义核对可比性，不用不同品种或阶段直接生成提前天数。
- [ ] 已审核日历按批次生成农事时间窗事项；无日历或依据不足时显示缺口，不自动给用量。
- [ ] 历史复盘只并列农事、天气与后续变化，不自动推断因果或收益。

**验收：** R13、R17、R18、R32对应样例可由程序复算、由技术员审阅；输出`C01.md`。

### C02 可撤回且有权限的知识检索

**依赖：** A01、B02、G09/G10。

- [ ] 同步权威资料只读副本，记录来源、审核、版本及撤回；扫描件未经识别与校核不视为已读。
- [ ] 切分保留标题、表头、单位和限制；中文关键词检索先用真实农业词汇测试分词与匹配，不默认数据库初始配置已满足要求。
- [ ] 关键词和向量结果都先限定权限与有效版本；引用和文件链接再次鉴权。向量记录模型、维度和文档版本，换模型不混用旧索引。
- [ ] 在同一评测集比较关键词、向量、混合及可选重排；逐环节记录耗时，先证明质量增益再采用增加延迟或费用的步骤。
- [ ] 撤回资料后，新检索、缓存和新回答不再使用；历史回答保留版本及来源失效标记。

**验收：** 无依据、无权限、已撤回、表格单位跨段、多个来源冲突均有样例；输出`C02.md`。

### C03 受限问答与模型运行记录

**依赖：** C01/C02、G10。

- [ ] 定义工具白名单和严格输入输出，分别列只读、草稿、派单与外发；模型只可调用当前用户有权的已定义查询。
- [ ] 保留模型、提示词、检索参数、输入引用、响应、截断标志、耗时和费用；凭据及不必要个人信息不进入日志。
- [ ] 对同一问题分别测试正常、资料不足、缺条件、服务超时、预算限制和备用切换；失败不成为正常回答。
- [ ] 对模型返回的数字、证据ID和必需限制字段做程序校验；语义是否有据仍由评测及人工审阅判断，不把字段校验说成证明结论正确。
- [ ] 专家只访问明确授权事项；推送渠道先实际验证，消息内使用受控链接，授权失效后禁止继续读取。

**验收：** 无权工具请求被后台拒绝；重复运行与错误状态有记录；敏感字段不外发；输出`C03.md`。

### C04 简报审阅 正式任务与周月报

**依赖：** C01—C03、B06。

- [ ] 规则产生事项列表，模型可排序、合并表达但不得漏掉事项或数据限制；历史补传事项单列。
- [ ] 技术员逐条采纳、修改、驳回；原草稿与人工修改分别保存，驳回记录原因。
- [ ] 老板版与工人端按权限生成，不能将不确定改写为正常；正式派单要求dispatch权限，对外推送要求share权限并确认范围。
- [ ] 技术员未审阅时保持待审，通知替班人员；实时告警继续运行。模型不可用时使用程序简报供审阅。
- [ ] 周月报复用同一数据与质量口径，提供覆盖范围、待确认事项和缺口，保持草稿与正式版本分开。

**验收：** R06、R31、R32及任务权限边界；选一日数据完整回放审阅流程，输出`C04.md`。

### C05 图片复核及分环节效果验证

**依赖：** B04/B05、G10样本与许可。

- [ ] 选定具体开源项目、权重和依赖版本并核实许可；先离线评估本地样本，再接入独立执行进程。
- [ ] 结果追加原告警，不覆盖人工判断、重置认领时间或改变处置状态；失败明确显示未完成。
- [ ] 分别验证摄像头触发、平台接收、人员接收和模型判断；采用现场测试及未告警时段抽查，不能仅统计已进入模型的图片。
- [ ] 白天、夜间、雨雾分开记录样本和结果；样本不足标未验证，继续人工判断。
- [ ] 停止模型或制造积压，确认采集、企业微信和夜间电话仍正常。

**验收：** R08、R15、R16；保留输入图片的受控引用及版本，不把人员图片发给文字大模型；输出`C05.md`。

### C06 评测集 版本比较与用量管理

**依赖：** C01—C05、专业评测负责人。

- [ ] 建立固定问题集，覆盖有依据、无资料、撤回、无权、数据过期、来源冲突和超时；每题有预期行为和支持证据，不要求唯一文字答案。
- [ ] 评测记录model/prompt/retrieval/dataset四种版本；每轮单独保存，重要样例重复运行，汇总前不覆盖单轮结果。
- [ ] 指标包括证据支持、必要限制保留、越权拒绝、任务边界、逐环节耗时及费用；同一评测集比较改动前后。通过标准在运行前由负责人和技术员登记，不能在看到失败后改标准来宣称通过。
- [ ] 预算触及80%和上限分别验证；模型可以降级，严重告警电话不因模型或媒体预算被停止。
- [ ] 准备可重复的版本对比命令和报告，再把它纳入发布流程；不以安装了评测工具代替具备评测数据。

**验收：** R33、R35及固定评测逐题证据；输出`C06.md`。

### C07 试运行与一期整体验收

- [ ] 完成2至4周技术员试运行，收集采纳、修改、驳回、误报及资料缺口；讨论技术员处理负担，不只收满意度。
- [ ] 按总览复核36项一期要求，含1a/1b跨阶段项目；对新增数据量重测权限、实时链路、备份和恢复。
- [ ] 逐角色培训，操作卡和反馈入口更新；未解决问题有归属、影响范围和处置安排。
- [ ] 外部工程师审阅、构建与回归均有证据；准备发布说明、兼容迁移和回退操作。
- [ ] 正式推广范围以已通过的设备、人员、资料及模型场景为准，未验证场景保留限制。

输出`docs/acceptance/1c/C07.md`及一期综合验收记录；RPO/RTO等目标须用实际演练证明，不从文档配置值推定。
