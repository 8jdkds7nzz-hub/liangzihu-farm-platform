> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> 上行是writing-plans模板保留的执行提示。实际执行以用户授权和宿主可用能力为准，缺少同名技能时不宣称已调用，也不因此增加无必要的审批。

**Goal:** 让少量真实监测点形成“取数、显示、告警、通知、认领、核查、留痕”的完整流程，并能发现平台故障、验证备份恢复。

**Architecture:** 新建独立私有平台仓库；Next.js负责页面及接口，采集、告警、通知工作进程独立运行，共用PostgreSQL。使用数据库持久任务和通知记录，外部健康检查独立于业务进程和业务数据库。

**Tech Stack:** TypeScript、Next.js App Router、React、pg、PostgreSQL与PostGIS、对象存储、Node测试运行器与tsx。原参考基线为Next.js 16.2.3；A00因实际依赖审计结果升级并锁定Next.js 16.3.8、React 19.2.4，Node要求至少22.15.0。实际安装、测试和版本记录见独立平台A00验收文档，后续升级单独验证。

**状态与路径:** A00本地开发基座已完成；A01及后续工作未开始。平台位于当前工作区的`智慧农业平台/`，为独立私有仓库。下文`src/`、`db/`、`workers/`、`tests/`均指该平台仓库根目录，不是当前报告网站。厂家真实字段由[总览](2026-10-01-智慧农业一期实施总览与工作项索引.md)G01—G06的交付确定；受阻工作项不能用猜测字段完成。

## Global Constraints

- 系统形态：一个系统，内部分模块；一套账号、一个数据库、电脑端加手机端。
- 代码仓库：新建私有git仓库，不放入现有报告网站。
- 原值永不覆盖；更正新增记录并保留理由。
- 缺测不是正常，未知不是故障；在线状态与数据新鲜度分开显示。
- 阈值和处方来自专业人员；系统和大模型不自定阈值，不给用量。
- 草稿与正式记录分开；不自动派单，不自动对外发送。
- 夜间有固定值班人员，能够到场处理。严重告警发出后3分钟仍无人认领，自动拨打当班人员电话。
- 联系人顺序为“当班人员 → 技术员 → 农场负责人”。
- 数据库最大可接受数据损失为15分钟；核心业务恢复时间目标为2小时。
- 主设计第4.1节的30天恢复窗口和第7节的5分钟合并提醒是推荐初值，需复核，不作为已实测结果。
- 实际开发修改`src/**`后必须通过构建；新增依赖登记package.json和锁文件。
- 1a保留受限专家角色与控制权限类型，所有设备控制默认关闭；闸门需另行完成插入式联合验收。

## 一 用户场景与阶段边界

主场景：技术员配置已审核规则，接入程序取得有效新测值并形成告警，当班人员从企业微信进入详情认领；没有认领时按夜间规则电话升级，核查及处置分别留痕。

必须同时支持的异常场景：单探头断采、厂家接口中断、旧数据补传、数值冲突、进程重启、回执未知、权限撤回、备份落后。1a不实现作物识别、每日大模型简报、完整农事模块、地图影像工作台或云端设备控制。

先交付可用的手机告警列表、详情、认领与核查页面，以及管理员的台账、规则和人员配置页面。界面朴素但状态明确；同一业务对象的电脑和手机入口引用相同记录。

内部主键采用UUID，页面可显示另行登记的中文名或人类可读编号；外部厂家编号单独保存。所有时间对外用带时区ISO字符串、数据库用`timestamptz`；原始设备时间另存，缺失时不能拿入库时间替换。金额和计量值在SQL中用适当精度的numeric，单位单独存。查询必须先限定授权对象，再计算分页、总数与导出。dispatch表示正式派单、share表示向外部接收人共享、act表示设备动作，三者不能互相代替。

HTTP接口由相同服务函数支撑，不在页面中另写一套权限或告警逻辑：

| 路由及方法 | 请求要点 | 成功结果及权限 |
|---|---|---|
| POST /api/v1/auth/login | 用户名、密码；需要时完成二次验证 | 建立独立平台会话；错误不透露账号是否存在 |
| GET /api/v1/auth/wecom/callback | 一次性state与code | 服务端交换身份并映射已启用账号，不由浏览器传入角色 |
| GET /api/v1/me | 当前会话 | 身份及有效能力；不返回密钥 |
| GET/POST /api/v1/objects | 分页或对象表单 | 只读授权范围；创建需configure |
| GET/POST /api/v1/devices | 对象、来源、外部编号等 | 设备台账及核实状态 |
| GET /api/v1/points/[id]/readings | from、to、游标 | 质量、新鲜度与原始时间，不能只返回数值 |
| GET /api/v1/alerts | 状态及授权对象过滤 | 活跃、已恢复待关闭、缺测等分开呈现 |
| POST /api/v1/alerts/[id]/claim | purpose、请求标识 | 返回唯一认领结果；越权403，竞争已被认领409 |
| POST /api/v1/alerts/[id]/events | 核查或处置类型、备注、依据 | 追加事件，不以保存备注自动关闭告警 |
| POST /api/v1/alerts/[id]/close | 核查与处置记录引用 | 满足关闭条件且有对应权限时关闭 |
| GET/POST /api/v1/maintenance | 对象及维护、复测或工单信息 | 范围授权，原值及更正可回查 |
| POST /api/v1/exports | 对象及时间范围 | 返回受控导出任务，下载时再次检查权限 |
| GET /api/v1/health/live | 存活检查 | 不含设备、人员、连接字符串等敏感内容 |

`tests/support/db.ts`的隔离实现：

```ts
import assert from 'node:assert/strict';
import { randomUUID } from 'node:crypto';
import pg, { type Pool } from 'pg';
import { loadMigrations, runMigrations } from '../../src/db/migrate';

export function requireTestDatabaseUrl(value = process.env.TEST_DATABASE_URL): string {
  assert(value, '缺少TEST_DATABASE_URL；测试不会自动使用DATABASE_URL');
  assert.equal(new URL(value).pathname, '/agri_test', '只允许agri_test测试库');
  return value;
}

export async function withDb<T>(fn: (pool: Pool) => Promise<T>, options: { migrate?: boolean } = {}): Promise<T> {
  const url = requireTestDatabaseUrl();
  const admin = new pg.Pool({ connectionString: url, max: 1, connectionTimeoutMillis: 2000 });
  const schema = 'test_' + randomUUID().replaceAll('-', '');
  let created = false;
  let pool: Pool | undefined;
  try {
    assert.equal((await admin.query('SELECT current_database() AS name')).rows[0].name, 'agri_test');
    await admin.query('CREATE SCHEMA ' + schema);
    created = true;
    pool = new pg.Pool({ connectionString: url, max: 4, connectionTimeoutMillis: 2000, options: '-c search_path=' + schema + ',public' });
    assert.equal((await pool.query('SELECT current_schema() AS name')).rows[0].name, schema, '测试schema未生效');
    if (options.migrate !== false) await runMigrations(pool, await loadMigrations());
    return await fn(pool);
  } finally {
    await pool?.end();
    try { if (created) await admin.query('DROP SCHEMA ' + schema + ' CASCADE'); }
    finally { await admin.end(); }
  }
}
```

迁移在当前schema创建业务表；扩展安装由测试库准备步骤完成。`TEST_DATABASE_URL`由测试进程环境注入，不从生产`.env`自动读取。首次运行测试命令前先创建对应测试文件，不以空测试套件算通过。

```ts
import type { ReadingInput } from './types';
export function canUseAsCurrent(x: ReadingInput, current: string | null, now: Date, maxAgeMs: number): boolean {
  if (x.quality !== 'valid' || x.value === null || !x.sampledAt) return false;
  const sampled = Date.parse(x.sampledAt);
  const age = now.getTime() - sampled;
  return Number.isFinite(sampled) && age >= 0 && age <= maxAgeMs
    && (current === null || sampled > Date.parse(current));
}
```

```ts
export interface RecoveryEvidence {
  failureAt: string; latestRecoverableAt: string; coreReadyAt: string;
  checksumPassed: boolean; accessPassed: boolean; notificationPassed: boolean;
  scope: string[]; checks: Record<string, boolean>; manifestRef: string;
}
export const CORE_RECOVERY_SCOPE = ['login','permissions','ingest','alarm_notice','night_phone','farm_record_read_write'] as const;
export function checkRecovery(e: RecoveryEvidence, requiredScope: readonly string[] = CORE_RECOVERY_SCOPE) {
  const reasons: string[] = [];
  const times = [e.failureAt,e.latestRecoverableAt,e.coreReadyAt].map(Date.parse);
  const [failure,recoverable,ready] = times;
  if (!times.every(Number.isFinite)) reasons.push('时间证据无效');
  if (recoverable > failure || failure - recoverable > 900_000) reasons.push('恢复点不满足15分钟');
  if (ready < failure || ready - failure > 7_200_000) reasons.push('恢复时间不满足2小时');
  if (!e.checksumPassed || !e.accessPassed || !e.notificationPassed) reasons.push('业务校验未通过');
  if (!e.manifestRef || !e.scope.length) reasons.push('范围或清单缺失');
  if (requiredScope.some(k => !e.scope.includes(k) || e.checks[k] !== true)) reasons.push('本次要求的功能未全部通过');
  const fullScope = CORE_RECOVERY_SCOPE.every(k => e.scope.includes(k) && e.checks[k] === true);
  return { pass: reasons.length === 0, fullScope, reasons };
}
```

1a可传入已交付的前五项范围进行阶段验证，但fullScope为false时不能宣称一期全部核心功能恢复达标；1b农事可用后及C07综合验收使用默认完整范围。

**验收：** 运维人员凭操作卡能恢复并说明证据，外部监测在核心系统停止时仍可通知。证据`A10.md`。
