# 管理员操作卡

1. 首次本地登录使用`.local/初始管理员凭据.json`，绑定自己的验证器并保存一次性恢复码。私有文件、密钥和联系方式不放进Git、截图或聊天。
2. 在“配置管理”按来源登记对象、厂家来源、设备、测点和批次。合同数量、预算数量及现场实物分开；核对实物后才确认“已核实”。不把未确认点位批量绑定到塘口。
3. 逐对象授予查看、记录、认领、审核、配置、导出等动作。管理员身份不自动读取全场数据。停用离职/转岗账号并撤回授权，复核遗留认领和工单。
4. 在“规则审核”由专业人员填写依据并审核，再启用。换塘前停用旧对象规则；已经产生测值的历史绑定不能回改。
5. 核实“值班安排”、现场可到达人员、升级顺序、联系方式与呼叫等待时限。保存联系方式不等于企业微信或电话已经接通；必须另跑厂家和登记测试对象的实机验收。
6. 每班查看“运行与费用”：核心进程最近运行/成功处理、待核回执、失败任务、备份恢复点和预算80%提醒。未知费用保留待核，严重电话不因预算额度被关闭。
7. 导出按对象和时段生成，文件只供原申请人下载且再次检查权限，24小时到期。完整数据库和原始报文恢复采用备份，不把JSON业务导出当成完整数据库备份。

本地维护命令（在独立平台目录执行）：

```sh
pnpm db:migrate
pnpm registry:setup
pnpm ops:setup
pnpm ops:health --once
pnpm ops:restore-drill
```

`ops:restore-drill`只操作agri_test的随机schema；本地合成演练不能签生产RPO/RTO。当前健康检查未全部就绪是外部依赖未齐的真实状态。生产G06操作卡必须补齐NAS/云备份链、取回方式、独立权限、人员及实际资源后再执行。

发生事故时先停止可能重放的后台任务，保留原记录与回执；先核对授权、未决发送和备份校验，再恢复处理。结果未知的电话不能盲目重发，禁止执行任何未联合验收的设备控制。
