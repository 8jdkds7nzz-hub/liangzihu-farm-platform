# 统一检查与验收产物

当前入口已从Q01扩展到工程完善版；[原Q01交付](../acceptance/产品化/Q01.md)保留当时结果，最新范围和实际证据见[工程交付核对](../acceptance/产品化/工程完善交付核对.md)。完整配置、Linux CI、发布和清理步骤见[操作卡](工程回归与发布操作卡.md)。

## 三个入口

| 命令 | 范围 |
|---|---|
| `pnpm check` | 类型检查、全部单元测试 |
| `pnpm check:core` | 独立环境、构建、固定核心数据库/HTTP浏览器子集、监测、归档及需求引用 |
| `pnpm check:delivery` | 完整17步，增加全部数据库/浏览器、本地模型评测、升级回退、四组恢复和10分钟持续运行 |

core/delivery必须先在只准备测试配置的独立副本执行`pnpm test:setup`。检查核对实际库、角色、实例标记及容器，拒绝开发/生产环境文件；不会自动操作原开发库。完整检查含正式构建，不在正在提供服务的目录覆盖`.next`。

core不要求模型文件，不能当作完整交付。delivery缺模型、浏览器、数据库或其他前置时，相关步骤记录blocked，整轮非零退出。原有分项命令仍可用；`ops:field-restore`与基础恢复脚本同源，统一入口不重复计数。

## 每轮记录

每次检查生成`.local/验证记录/<时间及随机后缀>/`，包含原子保存的`运行记录.json`、逐步日志和`产物/`。截图、评测及恢复文件都进入本轮目录，不再覆盖`docs/acceptance/`或`docs/evaluations/`历史原件。

记录包含确切提交、源码摘要、构建ID、环境、步骤、耗时、退出码、测试统计、失败用例和文件哈希。源码前后变化、历史证据变化、失败、跳过、中断或前置不足均不能签整轮通过。同目录排他锁防止两轮检查竞争构建；运行中的步骤按周期显示进度。

| 状态 | 含义 |
|---|---|
| running | 正在执行；尚无完成结论 |
| passed | 此步执行完成并符合判定，仍须看整轮结果 |
| failed | 程序失败、启动失败或超时 |
| blocked | 前置或依赖不足，未执行 |
| incomplete | 零退出但用例跳过、取消、待办或统计不完整 |
| interrupted | 被终止，不能作为完成证明 |

同版本重跑可追加`--retry-of <先前运行编号>`。新一轮完整执行自己的范围，原失败不删除；同源码和环境下重跑成功标为不稳定线索，不把它包装成从未失败。

## 公开与私有

`pnpm check:report`生成白名单公开摘要，只有已核格式的运行环境、固定步骤/错误代码、状态、数字和提交/摘要信息。完整命令、失败文本、私有路径、原件、备份转储和密钥不复制进公开摘要。GitHub只上传摘要，不整包上传运行目录。

私有日志和恢复文件继续被Git忽略。交付时选择已核对、脱敏的证据复制到新的文档路径，并登记原运行与哈希。错误记录保留；历史证据发生变化时只报告，不自动还原或删除用户文件。

## 结果边界

独立测试数按一次完整套件记录，不累计定向重跑、远端重复运行、评测题数或恢复动作。131条需求引用核对证明文件可追溯，不等于逐条语义断言覆盖率，也不关闭G01—G18。

候选发布清单还要求干净提交、同一源码和构建、升级及10分钟证据齐全。所有这些都是工程验收；真实设备、人员、专业方法、生产RPO/RTO仍按[试点交接](../试点/接入依赖与验收总表.md)验证。
