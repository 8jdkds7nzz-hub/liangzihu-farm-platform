# 统一检查与验收产物

Q01在现有测试之上增加两个入口。运行前先在本仓库安装锁定依赖；快检不需要数据库，完整交付检查需要已有的隔离测试环境。它们都不安装模型、不准备生产设备，也不代替现场验收。

## 两个入口

```sh
pnpm check
pnpm check:delivery
```

`pnpm check`执行类型检查和全部单元测试。`pnpm check:delivery`按顺序执行下表13项。**完整检查含正式构建，应在独立工作树或已停止服务的目录运行；不要覆盖正在提供服务的`.next`。**

| 步骤ID | 内容 | 必要条件 |
|---|---|---|
| typecheck | `pnpm typecheck` | 已安装依赖 |
| unit | `tests/unit/*.test.ts` | 已安装依赖 |
| build | `pnpm build`，包括生成Cesium资源 | 当前目录没有正在使用这份构建的服务 |
| database | `tests/integration/*.test.ts` | 可连接的agri_test、完整固定版本模型缓存 |
| browser-http | `tests/acceptance/*.test.ts` | 本轮构建通过、agri_test、模型缓存、Chromium |
| monitor | `tests/acceptance/*.test.mjs` | Node.js |
| archive | `tests/acceptance/wal-archive.test.py` | Python 3 |
| retrieval | `tools/evaluate.ts` | agri_test、固定模型缓存 |
| assistant | `tools/evaluate-assistant.ts --mode fixture` | agri_test、固定模型缓存；不调用真实外部模型 |
| restore-phase1 | `ops/restore-check.ts` | 本机测试容器、模型缓存 |
| restore-phase2 | `ops/phase2-restore.ts` | 同上 |
| restore-phase3 | `ops/phase3-restore.ts` | 同上 |
| restore-phase4 | `ops/phase4-restore.ts` | 同上 |

`ops:field-restore`与基础恢复脚本相同，因此不再执行第二次。原`pnpm test`及各分项命令继续存在，未被更名；但`pnpm test`只含单元和数据库，不能当完整交付入口。

## 前置条件

检查入口从环境变量或本机`.env.test.local`取得`TEST_DATABASE_URL`，只接受`agri_test`；从文件只导入这个键，不导入开发身份密钥。Next.js构建仍会按框架规则加载当前副本的环境文件，因此完整检查应使用只准备测试配置的独立副本，不复制开发`.env.local`。所有检查子进程关闭真实外部读取、通知和模型消费；个别测试会在进程内通过显式替身验证相关分支。

本机恢复程序仍使用现有`liangzihu-farm-db`容器、`127.0.0.1:55432`和`agri_tester`。其他测试库部署方式可供一般数据库检查，但不能据此运行这套写死本机容器的恢复命令；前置不符时恢复步骤标记阻塞。

模型缓存默认`.local/models`，可通过`MODEL_CACHE_ROOT`引用已有缓存。需要的固定版本包括BGE中文向量、YOLOS-tiny、SigLIP2；具体版本由检查入口与现有推理脚本共同核对。完整数据库/浏览器套件包含实际本地推理，因此这里保守要求完整缓存，不在缺模型时假装跑过全套。

缺模型可按[本地运行说明](本地开发与运行.md)单独执行已存在的模型准备命令；缺Chromium可单独安装锁定版本的浏览器。统一检查本身不自动下载或购买资源。

## 到哪里看结果

每次统一检查都会打印`.local/验证记录/<时间及随机后缀>/运行记录.json`的位置。目录内包含：

- `运行记录.json`：范围、提交和源码摘要、各步状态/耗时/退出码、统计、历史证据核对和文件哈希。
- `日志/`：逐步完整输出。失败时先看对应日志，不把一次重试成功覆盖上一次失败。
- `产物/验收/`：本轮截图、浏览器及模型工程记录，沿用原阶段子目录方便比较。
- `产物/评测/`：本轮检索/助手评测JSON。
- `产物/恢复/`：仅测试库的转储、模拟密钥、私有文件及恢复结果；不可当公开附件。

这些目录被Git忽略，不自动上传。日志和恢复文件可能含本机诊断内容或测试密钥，交付时只挑选核对过的脱敏结果，复制到新的文档目录并登记来源及哈希；不得整包提交。已有`docs/acceptance/`和`docs/evaluations/`仍是历史交付证据，不再作为运行输出目录。

单独执行原浏览器、评测或恢复命令时，产物辅助程序也会新建私有目录并提示路径；多进程测试可能各有目录。只有统一入口才提供完整的步骤汇总、前置核查与前后证据比对，单项成功不能替代完整交付。

## 如何读状态

| 状态 | 含义 | 下一步 |
|---|---|---|
| passed | 该步已完成，退出码和可解析统计符合要求 | 仍需看本轮其他步骤 |
| failed | 失败、启动失败或超时 | 查看该步私有日志并复现 |
| blocked | 缺前置，或依赖步骤未通过，未执行该步 | 补具体条件后开新一轮 |
| incomplete | 退出码为0但用例有跳过/待办/取消，或缺少有效统计 | 不算完整通过，检查原因 |
| interrupted | 本轮被终止，该步未完成 | 保留本轮记录，确认清理后再运行 |

只有所有必要步骤都通过、证据目录前后未变、产物清单完成，统一命令才返回0。错误和未执行均返回非零；统计按该次套件记录，不把重跑次数、评测题数、恢复动作加进独立测试用例总数。

证据检查发现文件被改动时只列出差异并失败，不自动还原或删除，以免掩盖原因或覆盖同时发生的用户修改。应先核实是测试写错位置还是有其他工作正在修改文档。

## 范围限制

本入口验证工程行为和隔离恢复。真实仁科/摄像/司空账户、企业微信和电话送达、闸门控制、专业阈值、生产容量与RPO/RTO仍需[G01—G18](../试点/接入依赖与验收总表.md)。Q02的远端CI尚未包含在Q01交付中。
