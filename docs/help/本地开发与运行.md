# 本地开发与运行

本文承接仓库首页的安装、配置和验证细节，适用于当前本地工程验证版。产品介绍与完成状态见[README](../../README.md)，逐期交付证据见[开发文档入口](../README.md)。

## 环境与首次启动

需要 Node.js ≥ 22.15.0、pnpm 10.33.0、Git 和已启动的 Docker Desktop。Web 默认监听 `127.0.0.1:3100`；专属数据库监听 `127.0.0.1:55432`。当前 Docker Compose 配置提供数据库，Web 和 workers 由本机 Node.js 运行。

在本仓库目录依次执行：

```sh
pnpm install --frozen-lockfile
pnpm db:setup
pnpm db:migrate
pnpm identity:setup
pnpm registry:setup
pnpm ops:setup
pnpm dev
```

`db:setup` 生成私有数据库凭据，构建专属 PostGIS / pgvector 镜像并创建 `agri_dev`、`agri_test` 及各自角色。`identity:setup` 建立初始管理员与身份加密配置；`registry:setup` 只建立场区入口和管理员授权；`ops:setup` 准备独立健康检查凭据。环境文件由这些脚本生成，不需要把 `.env.example` 整份覆盖为现有环境文件。

已有账号、场区和受管理配置会先核对，重复初始化不会重置已有密码。同名数据库资源存在但本目录缺少凭据时，脚本会停止；应恢复对应凭据并核对归属，不要删除原数据库重新初始化。

## 登录与首次使用

访问 **http://127.0.0.1:3100/login**。初始管理员信息保存在 Git 忽略的 `.local/初始管理员凭据.json`；请存入自己的密码管理器后按初始化说明处理该文件。不要把文件内容贴到 Issue 或 README。

`IDENTITY_MFA_REQUIRED` 未设置或为 `1` 时，按页面提示使用验证器和恢复码；为 `0` 时使用账号密码登录，修改配置后需要重启 Web。2026-10-03 原开发机按用户选择保留了 `0`，这项本机设置不随 Git 克隆到新电脑。[登录配置说明](../specs/2026-10-02-账号密码登录简化.md)

登录后先进入“配置管理”登记已核实对象、设备、测点、批次及人员授权。开发库不预填虚构设备、库存、阈值、联系人或轨迹；空白页面不代表初始化失败。验收截图中的合成数据只用于临时测试环境。

## 后台进程与模型

**每条 worker 命令单独开一个终端，工作目录都在本仓库。** 前台 `pnpm dev` 不会自动启动这些后台进程。

| 命令 | 处理内容与条件 |
|---|---|
| `pnpm worker:alarms` | 告警规则与状态处理 |
| `pnpm worker:notifications` | 通知规划与升级；真实发送按授权开关和实际配置控制 |
| `pnpm worker:media` | 私有文件、预览、分块原件及已授权远程下载 |
| `pnpm worker:knowledge` | 知识资料处理及本地向量 |
| `pnpm worker:intelligence` | 问答与简报后台任务；外部模型请求默认关闭 |
| `pnpm worker:image-review` | 本地 YOLOS 图片复核 |
| `pnpm worker:terrain` | 私有三维模型核验与处理 |
| `pnpm worker:agronomy` | 作物照片、GeoTIFF 指数及已核只读抓图调度 |
| `pnpm worker:management` | 四期综合指标，保存固定输入和结果；不调用外部模型或执行财务动作 |
| `pnpm worker:ingest` | 按已核来源契约采集；须先完成 G02 输入核对 |
| `pnpm worker:weather` | 已配置和风天气来源的只读同步 |
| `pnpm worker:cameras` | 已核监控来源的只读任务 |
| `pnpm worker:flighthub` | 已核司空来源的航次与文件任务 |

厂家与天气读取条件以[环境配置示例](../../.env.example)和对应接入记录为准。启动进程不表示外部接入已经核验；通知默认只规划任务，不执行真实发送。

向量与图片模型第一次使用前执行：

```sh
pnpm models:prepare
```

作物候选实验另外准备固定版本的 SigLIP2 权重：

```sh
pnpm models:crop-prepare
```

准备权重需要联网，之后本地推理使用本机文件，不把输入文字或图片上传到模型下载站。作物实验 `CROP_MODEL_EVALUATION_ENABLED` 默认是 `0`；开启工程实验也不能代替农业效果验收。权重与输入原件都不进入 Git 或 `public/`。

## 厂家、天气与原件

仁科采集已有契约配置下的只读 HTTP 链和文件回放；合成回放只允许测试库。真实字段、账户和报文仍待核实，不能仅凭令牌宣告接入成功。

天气从“分析复盘 → 只读天气连接与同步”管理。先在配置管理登记 `qweather` 来源，再登记接口、许可与核实依据，最后配置已确认网格；凭据和全局开关由部署者另行配置。来源没有发布时间时保持空值，不拿接收时间替代。[天气接入记录](../acceptance/1c/只读天气接入验收.md)

“监控与航次 → 下载链接转入私有原件库”可以把已取得只读授权、已解密的链接关联到既有事件或航次文件。链接加密保存，media worker 负责下载、校验与入库。部署者须核实精确 CDN 域名，远程下载默认关闭。[原件接入记录](../acceptance/1b/监控与航次原件接入验收.md)

小原件入口保留 20 MiB 限制；大文件走分块上传和后台处理链，当前默认 2 GiB，实际容量须另行测试。完整导出支持受控 JSON 和逐文件再鉴权的 `tar.gz` 原件包。S3 配置项见 `.env.example`，本地第二目录不能当作异地备份。

三维包及多光谱都有格式、坐标、文件数量和大小限制，详见[三维操作卡](三维与测绘资料操作卡.md)与[3C 操作卡](三期3c操作卡.md)。不要把“文件上传成功”当成“数据可用于地形或农业判断”。

真实控制执行适配器尚未实现，当前没有可通过开关启用的下发链。[G15 交接要求](../contracts/三期真实资料与设备适配交接.md)

## 数据库与私有配置

`agri_dev` 与 `agri_test` 使用独立角色，测试角色不能连接开发库。现有主机 PostgreSQL 和外层报告网站数据库不在本项目初始化范围内。数据库镜像固定摘要，Apple 芯片机器按 Compose 中的架构兼容配置运行。

`.env.local`、`.env.test.local`、`.env.docker.local`、`.env.health.local` 和 `.local/` 被 Git 忽略。初始化生成的私有凭据文件使用 `0600` 权限；数据库备份与身份加密密钥须分别保管。真实生产密钥托管与恢复仍按 G06 验收。

数据库迁移目前追加至 `000—043`，执行时记录校验值；不要修改已应用迁移。`008` 核对历史对象引用，`009` 保留字段契约版本，`010` 保留反馈处理记录；三期新增 `035—038`，四期新增 `039—043`。缺失实物资料时不创建占位设备冒充现场对象。

普通事务不使用全局锁，只对迁移、相关记录或同一请求标识串行。Web 默认最多 5 个数据库连接，采集、告警和通知进程分别默认 2 个，单条查询默认 10 秒；这些默认值不是生产容量承诺。

## 验证与恢复

当前统一入口：日常用`pnpm check`，核心工程回归用`pnpm check:core`，完整交付用`pnpm check:delivery`。core/delivery先按[工程回归与发布操作卡](工程回归与发布操作卡.md)准备独立测试环境，包含正式构建，不能覆盖当前运行服务的`.next`。每轮结果保存在`.local/验证记录/`，失败或缺前置不算通过；下列原有分项命令继续可用。

先完成本地数据库初始化。数据库和浏览器测试在 `agri_test` 内创建各自随机 schema，使用测试身份和独立端口，不使用本机管理员凭据。

基础检查：

```sh
pnpm typecheck
pnpm test:unit
pnpm test:db
pnpm build
pnpm audit --prod
```

HTTP、浏览器及专项检查，缺少浏览器时先安装当前锁定版本的 Chromium：

```sh
pnpm exec playwright install chromium
pnpm test:http
pnpm test:browser
pnpm test:compat
pnpm test:monitor
pnpm test:health
pnpm test:field
pnpm test:intelligence
pnpm test:weather
pnpm evaluate
pnpm evaluate:assistant
```

`test:browser` 仅指脚本列出的基础浏览器套件，不是所有阶段的总入口。二、三期附加用例位于 `tests/acceptance/`，整套 HTTP / 浏览器用例可运行：

```sh
node --env-file=.env.test.local --import tsx --test --test-concurrency=1 tests/acceptance/*.test.ts
```

`test:monitor` 是单独的 `.mjs` 用例。另有 Python 归档检查，需要 Python 3：

```sh
python3 tests/acceptance/wal-archive.test.py
```

最新统一检查结果见[工程完善交付记录](../acceptance/产品化/工程完善交付核对.md)，各期旧证据保留原日期与范围；不能把定向套件或重复执行数量当成新的全量结果。

恢复演练：

```sh
pnpm ops:restore-drill
pnpm ops:field-restore
pnpm ops:phase2-restore
pnpm ops:phase3-restore
pnpm ops:phase4-restore
```

演练会实际备份、删除并恢复自己在测试库创建的随机 schema；不操作 `agri_dev/public`。`ops:field-restore` 与基础恢复命令当前调用同一脚本；二期、三期、四期脚本另核对各自新增业务与文件。四期比对191张应用表、27张非空新增表和7份私有文件，包含跨账号导入身份、试验旧快照及中断报告任务。私有演练副本留在忽略的 `.local/`。本地耗时不代表生产 RPO / RTO，生产恢复仍未验收。

## 正式构建与健康检查

需要运行本地正式构建时，在开发进程停止后执行：

```sh
pnpm build
pnpm start
```

不要在正在提供服务的同一目录覆盖 `.next` 构建；需要并行验证时使用独立工作副本。Web、worker 和独立监测分别运行。

```sh
pnpm ops:health
```

`/api/v1/health/live` 只证明 Web 可以响应。受独立凭据保护的 `/api/v1/health/ready` 还检查核心进程和备份；条件不足时返回 `503` 表示未就绪。独立监测读取 `.env.health.local`，真实对外告警默认关闭。

## 常见问题

| 现象 | 核对方法 |
|---|---|
| 克隆仓库出现 404 或无权限 | 四期核对时仓库已公开；先检查地址、网络和Git凭据，后续可见性以GitHub设置为准 |
| 数据库无法初始化 | 确认 Docker 已启动、端口未占用，已有资源与本目录凭据相符；不重置其他库 |
| 页面能开，但任务停在待处理 | 检查对应 worker、模型文件和已核来源配置；外部请求关闭时按状态提示处理 |
| 首次登录要求验证器 | 检查当前环境的 `IDENTITY_MFA_REQUIRED`，新环境默认启用二次验证 |
| `/health/live` 正常而 `/health/ready` 为 503 | 检查受保护的就绪结果及“运行与费用”页面，核实进程与备份，不以存活替代就绪 |
| 构建目录出现带编号副本 | 原工作区曾出现此情况；已关闭 Turbopack 文件系统持久缓存，并只排除生成类型目录中的带空格副本，源码仍接受检查 |

运行异常的反馈不要附带完整环境文件或带密码的连接串。现场验收未完成前，仍依现有值班和厂家系统工作。
